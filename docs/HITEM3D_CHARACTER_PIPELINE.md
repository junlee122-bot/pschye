# Hi3D 캐릭터 실메시 제작 파이프라인

이 파이프라인은 기존의 절차적 도형 GLB를 최종 결과물로 사용하지 않는다. 캐릭터 설정화에서 일관된 다면 원화를 만들고, Hi3D의 이미지 기반 생성 모델로 고밀도 PBR GLB를 만든 뒤 검수·리토폴로지·리깅을 거쳐 게임 런타임 모델로 승격한다.

## 제작 단계

1. 설정집 원화에서 얼굴, 복식, 장비, 색상 규칙을 고정한다.
2. 정면·후면·좌측·우측의 중립 자세 원화를 만든다.
3. `pnpm models:hitem:prepare -- --character=<id>`로 깨끗한 입력 이미지를 만든다.
4. `pnpm models:hitem:generate -- --character=<id>`로 비용 없는 드라이런을 확인한다.
5. 인증과 크레딧을 확인한 뒤에만 실제 작업을 제출한다.
6. 받은 GLB를 구조 검사와 시각 검수에 통과시킨다.
7. 원본은 `review` 등급으로 보관하고, 리토폴로지·리깅·LOD 제작 후에만 `production`으로 승격한다.

## 인증

`.env.3d.example`을 `.env.3d.local`로 복사하고 Hi3D 콘솔에서 발급받은 값을 로컬에만 기록한다.

```dotenv
HITEM3D_CLIENT_ID=
HITEM3D_CLIENT_SECRET=
HITEM3D_ALLOW_SPEND=false
```

실제 크레딧 사용은 다음 두 조건이 동시에 충족될 때만 가능하다.

- 명령에 `--execute`가 있음
- `HITEM3D_ALLOW_SPEND=true`

```powershell
pnpm models:hitem:generate -- --character=raon --execute
```

## 원화 품질 기준

- 네 시점에서 머리 길이, 체형, 어깨 폭, 부츠 높이가 일치해야 한다.
- 의상 절개선, 벨트, 가방, 견갑, 문양의 위치가 시점마다 이어져야 한다.
- 무기나 소품이 신체 실루엣을 과도하게 가리지 않아야 한다.
- 배경은 단색에 가깝고 그림자와 원근 왜곡이 약해야 한다.
- 다른 인물의 신체나 장비 조각이 크롭에 남아서는 안 된다.
- 손가락과 발이 프레임 밖으로 잘리지 않아야 한다.

## 자동 원본 게이트

다운로드 직후 다음 조건을 만족하지 못한 GLB는 카탈로그에 승격하지 않는다.

- 유효한 GLB 2.0 헤더와 길이
- 파일 크기 1 MB 이상
- 메시·재질·노드 각각 1개 이상
- 삼각형 50,000개 이상 2,500,000개 이하
- 생성 출처, 작업 ID, 입력 시점 기록 보존

자동 게이트는 파일 손상과 비정상 저밀도 출력을 걸러내는 최소 기준이다. 캐릭터 닮음, 손·얼굴 구조, 옷의 관통, 후면 완성도는 반드시 시각 검수가 필요하다.

## 게임용 승격 기준

Hi3D 원본은 고밀도 조형 원본이며 곧바로 플레이어 캐릭터로 사용하지 않는다.

- 얼굴과 손의 형상 교정
- 분리되어야 할 장비와 의상 파츠 정리
- 변형 가능한 관절 토폴로지로 리토폴로지
- 휴머노이드 스켈레톤과 스킨 웨이트
- 표정용 블렌드셰이프
- PBR 텍스처 베이크
- LOD0, LOD1, LOD2, 임포스터 제작
- 걷기·달리기·회피·공격 애니메이션 검증
- 실제 게임 카메라 거리에서 실루엣과 재질 재검수

## 현재 대표 입력

- 캐릭터: 라온
- 원본: `public/art/3d-inputs/raon-turnaround-v1.png`
- 생성 입력: `artifacts/3d/hitem3d-inputs/raon/`
- 시점: 정면, 후면, 좌측, 우측
- 목표: `hitem3dv2.1`, `1536fast`, PBR GLB, 약 100만 페이스

라온 대표 모델이 시각 검수와 게임용 후처리 기준을 통과한 뒤 같은 규격을 하도리, 카즈린, 카인, 레오와 주요 1세대 인물로 확장한다.

## 저장 공간

고밀도 GLB, 텍스처, 후처리 사본, 프로덕션 빌드를 함께 다루려면 최소 수 GB의 여유 공간이 필요하다. 작업 전 C: 드라이브에 10 GB 이상을 확보하는 것을 권장한다.
