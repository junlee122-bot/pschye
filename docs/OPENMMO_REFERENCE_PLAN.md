# 《라온제나》 OpenMMO 참고 설계안

## 1. 결론

《라온제나》는 OpenMMO를 그대로 따라 MMORPG가 되는 것보다, 다음 형태가 가장 적합하다.

> 라온 한 사람의 시점으로 진행되는 서사형 액션 RPG를 중심에 두고, OpenMMO의 데이터 중심 설계·권위적 시뮬레이션·계층형 AI·모듈식 월드 제작 방식을 내부 구조로 받아들인다.

플레이어는 처음부터 끝까지 라온이다. 다른 유저나 AI 에이전트가 본편의 라온을 대신하거나 정사를 변경하지 않는다. 온라인 기능을 추가하더라도 본편 외의 원정, 훈련, 기록 재현에 한정한다.

## 2. OpenMMO에서 확인한 강점

OpenMMO는 다음 구조를 사용한다.

- Svelte·Three.js 기반 3D 클라이언트와 Rust 비동기 서버를 분리한다.
- 모든 전투 판정과 아이템 획득을 서버에서 검증한다.
- 플레이어와 AI 에이전트가 동일한 WebSocket 메시지를 사용한다.
- 몬스터 전투는 상태 머신으로, NPC 대화와 고수준 판단은 LLM으로 처리한다.
- 소스 데이터를 생성용 데이터와 런타임 JSON으로 분리한다.
- 방 단위 모듈을 조합하는 다층 건축 시스템을 사용한다.
- 월드·도로·강·생태 지역을 데이터와 절차 생성으로 관리한다.
- 첫 로딩의 셰이더 컴파일과 텍스처 비용을 측정하고 단계적으로 줄인다.

이 중 《라온제나》에 가장 가치 있는 것은 거대한 맵 자체가 아니라 **게임 규칙을 UI와 분리한 구조**다.

## 3. 현재 《라온제나》와의 차이

현재 프로젝트는 다음 기반을 이미 갖고 있다.

- React 19 + Vite + Phaser 3
- 라온의 기원 서사와 선택 기록
- 8개의 전술 임무
- 5부·86화·516개 장면의 전체 서사 원장
- 여섯 조장, 관계도, 성장, 장비, 시설, 파견, 일일 행동
- 명령점·적 의도·집중 연계·브레이크·사기·합동기 기반 전투
- 브라우저 localStorage 기반 단일 프로필

그러나 다음 한계가 있다.

1. 516개 장면은 탐색 가능한 설정 원장이지 실제 플레이 흐름에 연결된 장면 그래프가 아니다.
2. 전투 규칙은 엔진 내부에 존재하지만 플레이어가 라온의 검을 직접 다룬다는 감각이 약하다.
3. 월드, 본부, 임무, 활동이 각각 메뉴로 분리되어 하나의 장소를 걷는 감각이 부족하다.
4. 저장이 localStorage 하나에 묶여 있어 대형 RPG의 세이브 슬롯, 버전 마이그레이션, 체크포인트 복구에 약하다.
5. NPC는 고정 데이터이며 시간, 관계 기억, 사건 이후의 생활 변화가 없다.
6. 일부 한국어 문자열이 깨진 상태여서 시스템 확장 전에 인코딩 원장을 복구해야 한다.

## 4. 반드시 참고할 시스템

### 4.1 명령·이벤트 프로토콜

OpenMMO의 동일 프로토콜 원칙을 싱글플레이 구조에도 적용한다.

UI가 게임 상태를 직접 바꾸지 않고 반드시 `GameCommand`를 보낸다. 시뮬레이션은 명령을 검증한 뒤 `GameEvent`를 만든다.

예시 명령:

- `MoveRaon`
- `UseTechnique`
- `ParryAttack`
- `IssueCompanionOrder`
- `TalkToNpc`
- `ChooseDialogue`
- `PickUpEvidence`
- `RestAtHeadquarters`
- `BeginMission`

예시 이벤트:

- `RaonMoved`
- `TechniqueResolved`
- `PerfectParryTriggered`
- `BondMemoryAdded`
- `EvidenceRecovered`
- `CanonFlagChanged`
- `SceneUnlocked`

장점은 다음과 같다.

- 키보드, 게임패드, 터치 조작이 같은 규칙을 사용한다.
- 자동 전투와 튜토리얼 시연도 같은 명령을 재생할 수 있다.
- 전투 리플레이, 버그 재현, 세이브 복구가 쉬워진다.
- 나중에 선택적으로 협동 모드를 추가해도 규칙을 다시 만들 필요가 없다.

### 4.2 계층형 AI

OpenMMO처럼 모든 행동을 생성형 AI에 맡기지 않는다.

#### 1계층: 즉시 전투 AI

- 순찰
- 엄폐
- 사선 확보
- 공격 예고
- 회피
- 보호 대상 압박
- 부상 시 후퇴

고정 상태 머신이나 행동 트리로 처리한다. 반응이 즉각적이고 재현 가능해야 한다.

#### 2계층: 동료 전술 AI

각 조장은 라온의 명령과 자신의 성격을 함께 고려한다.

- 하도리: 가장 큰 위협을 고정하고 민간인과 라온 사이를 막는다.
- 카즈린: 목표 제거를 우선하지만 관계 성장 후 보호 명령을 존중한다.
- 카인: 초반에는 위험한 단독 돌진 확률이 높고, 성장에 따라 명령 이행도가 오른다.
- 레오: 전선 붕괴 지점을 자동 보강한다.
- 크리스: 측면, 장치, 지형 상호작용을 우선한다.

#### 3계층: 생활·대화 AI

고정 대사 원장을 우선한다. 생성형 대화는 정사를 바꾸지 않는 자유 대화에만 쓴다.

NPC 기억은 다음 세 층으로 분리한다.

- 역할 원장: 변하지 않는 성격과 금지 행동
- 인물 원장: 개인의 과거, 말투, 관계
- 기억 원장: 라온이 실제로 한 선택과 최근 사건

LLM이 없어도 핵심 서사는 항상 진행 가능해야 한다.

### 4.3 데이터 주도형 콘텐츠

OpenMMO의 `data-src → generated data` 구조를 참고해 516개 장면을 실제 게임 데이터로 승격한다.

권장 구조:

```text
content-src/
  sagas/
  episodes/
  scenes/
  dialogues/
  encounters/
  npcs/
  regions/
  items/
  techniques/
content-generated/
  manifest.json
  scenes.json
  encounters.json
  localization.ko.json
```

빌드 전에 검증 도구가 다음을 검사한다.

- 존재하지 않는 다음 장면 참조
- 정사상 사라진 권능의 현재 사용
- 죽은 인물의 잘못된 등장
- 해찬의 다리 장애 누락
- 마루 계약의 키티 예외 위반
- 라온이 알 수 없는 정보를 대사에서 선행 언급
- 필요한 배경·초상·음향 파일 누락

### 4.4 모듈식 본부

OpenMMO의 주택 건설은 그대로 넣지 않고 프시케 본부 성장으로 바꾼다.

플레이어가 직접 확장할 공간:

- 진훤의 훈련장
- 미르의 회복동
- 마루의 기록실
- 바이올렛 작전실
- 구세계 공방
- 제3기 추모관
- 제5기 구조 교실
- 제7기 숙소

각 방은 장식이 아니라 게임 기능과 장면을 가진다. 시설을 배치하면 동료의 동선, 밤 대화, 훈련 이벤트, 제작 가능 장비가 바뀐다.

### 4.5 지역 스트리밍

32km 절차 생성 월드를 그대로 도입하지 않는다. 서사의 밀도가 떨어지기 때문이다.

대신 8개의 수제작 대지역과 연결 통로를 사용한다.

1. 변방 마을과 주변 숲
2. 제국 수도
3. 프시케 본부
4. 회색 교각과 난민로
5. 저주받은 땅
6. 체시 공중 유적
7. 제3기 참사 지대
8. 빛의 폭발 중심지

각 대지역은 여러 셀로 나누어 필요한 셀만 로딩한다. 에피소드 진행에 따라 같은 장소의 NPC, 경비, 날씨, 파괴 상태, 소문이 달라진다.

## 5. 전투 재설계

OpenMMO의 D20 무작위 명중 공식은 《라온제나》의 검술 판타지와 맞지 않는다. 대신 서버 권위와 명확한 계산이라는 원칙만 가져온다.

### 핵심 장르

> 라온 직접 조작 + 전술 정지 명령 + 동료 연계가 결합된 2.5D 파티 액션 RPG

### 기본 루프

1. **읽기**: 적의 사선, 예고 공격, 보호 목표를 파악한다.
2. **열기**: 패링, 회피, 이능 관찰로 적의 자세를 무너뜨린다.
3. **잇기**: 라온이 동료에게 명령해 동일 목표에 연계를 쌓는다.
4. **꽃잎**: 브레이크된 적에게 해찬류의 연속 검로를 입력한다.
5. **선택**: 쓰러뜨릴지, 제압할지, 구조를 우선할지 결정한다.

### 라온 조작

- 이동과 거리 조절
- 약공격·강공격
- 방향 패링
- 회피 보법
- 이능 관찰
- 네 개의 검로 슬롯
- 시간 감속 전술 원형
- 동료 명령 휠

무작위 빗나감은 사용하지 않는다. 공격이 실패했다면 거리, 방어, 타이밍, 사선 중 하나가 화면에서 명확히 보여야 한다.

### 기존 시스템의 승격

- 명령점 → 전술 집중 게이지
- 집중 연계 → 동료의 실제 위치와 타이밍이 필요한 연계
- 브레이크 → 자세 붕괴
- 적 의도 → 바닥 사선·몸짓·음향으로 시각화
- 사기 → 제7기 공명 게이지
- 합동기 → 관계 장면에서 해금되는 서사형 피니셔
- 자비·통찰·결의 → 대사 선택만이 아니라 전투 해결 방식

### 세 경로의 플레이 차이

- 자비: 구조, 제압, 피해 분산, 민간인 생존 보너스
- 통찰: 약점 분석, 숨은 사선 발견, 기록 회수, 거짓 깃발 판별
- 결의: 패링 보상, 돌파, 브레이크 피해, 위험 감수

세 경로는 선악이 아니라 라온이 문제를 해결하는 습관이다. 어느 하나만 정답이 되어서는 안 된다.

## 6. 온라인 기능의 안전한 범위

본편을 MMO로 만들면 라온의 고정된 서사와 플레이어 자유가 충돌한다. 온라인 기능은 다음 순서가 적절하다.

### 1단계: 비동기 기록

- 다른 플레이어의 임무 편성 확인
- 보스 기록과 전투 리플레이 유령
- 구조율·증거 회수율 비교
- 선택 결과는 비율만 공개하고 정사는 바꾸지 않음

### 2단계: 본편 밖 협동 원정

- 제3기 참사 지대 수색
- 저주받은 땅 호송
- 체시 유적 방어
- 본편에서 라온이 아닌 프시케 일반 단원을 생성해 플레이

### 3단계: 살아 있는 본부

- 다른 플레이어의 단원이 본부 광장에 방문
- 훈련 기록 교환
- 장비 설계도와 방 꾸미기 공유

본편의 라온, 해찬, 라미, 진훤은 멀티플레이 캐릭터로 복제하지 않는다.

## 7. 도입하지 않을 요소

- 32km 전체 절차 생성 월드
- 플레이어가 본편 세계를 무제한 건축하는 시스템
- 일반적인 D&D 직업과 4d6 능력치 생성
- 모든 NPC의 무제한 생성형 대화
- 지상 아이템의 영구 공유 소유권
- 본편 정사를 바꾸는 PvP와 진영전
- 처음부터 Rust 서버와 대규모 WebSocket 인프라를 구축하는 것

이 기능들은 제작량을 크게 늘리지만 라온의 성장과 516개 장면을 더 재미있게 만들지는 않는다.

## 8. 구현 순서

### P0. 기반 복구

- 깨진 한국어 문자열 복구
- 콘텐츠 UTF-8 검증 테스트
- localStorage 버전 9 세이브 마이그레이션 고정
- 현재 8개 임무의 튜토리얼과 전투 피드백 재점검

### P1. 명령·이벤트 코어

- 순수 TypeScript 시뮬레이션 패키지 분리
- `GameCommand`, `GameEvent`, `GameSnapshot` 정의
- 전투 리플레이와 결정적 테스트 추가
- IndexedDB 기반 다중 세이브 슬롯 도입

### P2. 마을 버티컬 슬라이스

- 라온의 변방 마을을 이동 가능한 2.5D 지역으로 제작
- 카즈린·카인·테나와 자유 대화
- 마을 일과, 라면, 검술 놀이, 첫 사건
- 프시케 지원 선택과 출발
- 전투 튜토리얼 1회, 사회적 선택 2회, 탐색 사건 1회

### P3. 프시케 본부

- 모듈식 방과 시설
- 제7기 동료 생활 AI
- 훈련, 관계, 제작, 파견을 실제 공간 상호작용으로 통합
- 516개 장면 중 제1부 90개를 플레이 가능한 장면 그래프로 전환

### P4. 전투 2.0

- 라온 직접 조작
- 적 자세·사선·브레이크
- 전술 정지와 동료 명령
- 자비·통찰·결의 해결 방식
- 회색 교각 전체를 완성도 기준 버티컬 슬라이스로 제작

### P5. 살아 있는 지역

- 8개 대지역 셀 스트리밍
- 시간대·사건 단계별 NPC 배치
- 제국, 민간인, 반데닌, 체시 잔당 평판
- 증거와 기록에 따른 공식 역사 변화

### P6. 선택적 온라인

- 계정·클라우드 세이브
- 비동기 리플레이
- 본편 밖 2~4인 협동 원정
- 필요할 때만 권위 서버와 WebSocket 도입

## 9. 최우선 버티컬 슬라이스

첫 구현 목표는 거대한 월드가 아니라 다음 60~90분 구간이다.

> 변방 마을의 하루 → 카즈린과의 갈등 → 카인의 도발 → 작은 구조 사건 → 프시케 지원 결심 → 마을 밖 첫 전투 → 출발 전 밤 대화

이 구간에서 검증해야 할 것은 다섯 가지다.

1. 라온을 직접 움직이는 것만으로 재미있는가.
2. 대화 선택이 이후 장면과 전투 해결에 보이는 차이를 만드는가.
3. 동료 AI가 성격을 전투에서 드러내는가.
4. 전투의 읽기·열기·잇기·꽃잎 루프를 설명 없이 이해할 수 있는가.
5. 다시 마을을 걷고 사람들과 대화하고 싶게 만드는가.

이 슬라이스가 완성된 후에만 대지역, 온라인, 절차 생성 여부를 판단한다.
