# 첫 마을 구출 플레이 루프

## 범위와 근거

마을 이동 → 수로 대화 → 세 선택 중 하나 → 비살상 구출 → 마을 귀환과 반응 → 저장·이어하기를 한 번 실제로 완주하는 제작 단위다. `river-incident`의 장소·생물·구체 행동은 **각색 초안**이다. [원전 v3.1](source/world-bible-v3.1.md) §73도 「오프닝 설계안」이며, §75의 비살상 실험체 보호는 후속 시험의 방향을 참고한 것이다. 이 구현으로 새 역사나 능력을 정사로 확정하지 않는다.

- 원전 §53·76·77: 라온은 체능 기본기와 지구력이 부족하다. 강림의 지도, 마루 수련, 16꽃잎은 이후다. 걷기·짧은 피하기·부르기·표식·유인을 사용하며 본편의 성장 수치, 체능 기술, 검기, 극의를 가져오지 않는다.
- 감각은 가까운 위험과 길을 알아차리는 연출이다. 미래 예지, 권능, 라온의 신성 주입 실험 이력이나 완성된 능력명을 새로 확정하지 않는다.
- 구출 대상은 이름이 밝혀지지 않은 **아이**다. 기존 마을 주민 밀로와 동일인인지, 누구의 자녀인지 정하지 않는다. 생물의 정확한 종족·실험 경위도 확정하지 않는다.
- 카즈린은 숙련된 창술과 구조로 돕는다. 이 사건만으로 라온을 완성된 조장으로 인정하거나 자신의 종족관·운명관을 버리지는 않는다.

## 세 선택과 완료 사실

| 기존 선택 ID | 플레이 의도 | 귀환 반응 예시 |
|---|---|---|
| `save-child` · 연민 | 아이에게 길을 알려 주어 스스로 빠져나오게 한다. | 아이: “목소리가 들려서 움직일 수 있었어.” |
| `mark-safe-route` · 통찰 | 가까이서 파악한 길에 돌을 놓아 다른 사람도 이용하게 한다. | 도안: “네가 놓은 돌을 따라 빠져나왔어.” |
| `draw-the-beast` · 결의 | 생물의 시선을 끌고 카즈린이 아이를 꺼낼 틈을 만든 뒤 라온도 후퇴한다. | 카즈린: “그 틈에 아이를 꺼냈어. 너도 무사해서 다행이야.” |

세 경로의 공통 결과는 **아이의 안전, 생물의 생존, 라온의 귀환**이다. 생물의 체력을 0으로 만들거나 카즈린까지 이기는 전투가 아니다. 반응 문구는 위와 같은 작은 행동의 차이를 기억하며, 혈통·가족관계·미래의 결말을 덧붙이지 않는다.

## 이번 구현 규칙

`src/game/villageRescue.ts`는 5열×3행 턴 보드, `move`·`assist`·`guard`, 체력 5, 최대 24턴, 구출 진행 3단계를 정의한다. UI의 1열은 내부 좌표 `x=0`이다. 연민은 4~5열에서 도움, 통찰은 2·3·4열에 각각 한 번 표식, 결의는 3~5열에서 유인한다. 유효한 행동에만 한 턴이 흐르고, 행동 전에 예고된 행에서 행동을 마치면 체력 1을 잃는다. 방어는 한 턴을 써서 그 피해를 막는다.

구출 3단계 뒤 체력이 남은 채 1열로 철수하면 `return`, 마을 카즈린 `(478, 348)`과 거리 94 이내에서 귀환을 확인하면 `complete`다. 체력 0은 철수보다 먼저 실패로 처리하며, 24번째 행동에 살아서 철수하면 성공한다. 수치와 좌표는 게임 규칙이며 세계관 설정이 아니다.

상태 흐름은 `ready → active → return → complete`, 실패 시 `active → failed → active`(같은 선택으로 재도전)다. 순수 규칙 API는 `canApplyVillageRescueAction` / `resolveVillageRescueAction`, 프로필 연결은 `src/game/villageRescueProgression.ts`의 `getVillageRescue` / `startVillageRescue` / `applyVillageRescueAction` / `retryVillageRescue` / `completeVillageRescueReturn`이다.

구조 중단·재도전은 실패 뒤 다시 시도할 수 있는 게임 흐름이다. 아이나 라온의 죽음을 정사 결과로 저장하지 않는다. **선택 의도**인 성향·평가 점수·관계 수치는 선택할 때 기존 방식으로 한 번 기록한다. **구출 결과**인 플래그와 NPC의 완료 기억(`choice.result`)은 마을 귀환 때 한 번 기록한다. 실패·재도전·귀환으로 선택 수치를 더 주지 않으며, 선택 버튼만 누른 상태에서 결과 문장을 완료 기록으로 표시하지 않는다.

`saved-river-child`는 연민 전용 플래그이므로 공통 구출 완료의 단독 조건으로 사용하지 않는다. 이전 세이브의 `completedSceneIds`에 수로가 있거나 후속 장면·서장 완료에 도달했다면 완료 기록을 존중하고 재구출을 강요하지 않는다. **수로에서 선택만 하고 아직 장면을 마치지 않은 구세이브**는 `ready`로 이어간다. 이미 받은 수치와 선택은 보존하고, 미리 들어간 결과 플래그·NPC 완료 기억만 귀환까지 보류한다.

수로 사건은 앞 장면에서 **사흘 뒤**, 선발 공고는 사건에서 **일주일 뒤**다. 귀환 직후 공고 장면으로 이동할 때 시간 경과를 보여 주며, 같은 저녁에 선발관이 도착한 것처럼 이어 붙이지 않는다.

## 수동 이어하기 시나리오

연민 경로의 중간 새로고침과 구출·철수·마을 지도 복귀는 위와 같이 확인했다. 카즈린에게 걸어가는 중 브라우저 자동화 연결이 끊겨, 아래 시나리오 전체를 완주한 항목은 아직 없다. 자동검사와 부분 화면 확인을 전체 마을 플레이 루프의 수동 완주로 간주하지 않는다.

1. 새 시작에서 마을의 목표 지점으로 이동하고 대화하여 `river-incident`까지 진행한다. 아직 선택하지 않은 상태로 새로고침해 결과가 미리 생기지 않았는지 확인한다.
2. 세 경로를 각각 새 시작 또는 독립 테스트 세이브로 선택한다. 행동을 일부 수행한 뒤 새로고침해 경로·체력·턴·구조 진행이 보존되는지 확인한다.
3. 구조 3단계 완료 직후, 0열 철수 직후에 각각 새로고침한다. 마을 귀환을 아직 완료하지 않았다는 안내가 유지되어야 한다.
4. 마을에서 카즈린에게 돌아가 완료한다. 경로별 반응, 완료 기록, 다음 목표와 「일주일 뒤」 전환을 확인한다. 다시 로드하고 같은 상호작용을 반복해 중복 지급이 없는지 본다.
5. 체력 소진과 턴 제한을 각각 발생시킨 뒤 재도전한다. 실패가 사망 정사로 남지 않고 구출 결과도 기록되지 않으며, 새 시도의 상태는 초기화되고 기존 선택 수치는 유지되어야 한다.
6. 업데이트 전 수로 **선택만 한** 세이브는 선택·점수를 유지한 `ready`로, 수로 **장면 완료·후속 장면** 세이브는 재구출 없이 이어져야 한다. 어느 경우도 선택 보상을 다시 지급하지 않는다.

남은 체크 표시와 수동 검증 결과는 실제 브라우저에서 해당 시나리오를 확인한 뒤 갱신한다.
