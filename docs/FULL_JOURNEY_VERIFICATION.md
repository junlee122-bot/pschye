## 수정과 재현

- **슬롯/시도 입력 격리:** App의 초기 이야기 선택·마을 이동·구출에 슬롯 세대 확인, 구출 동작에 시도/턴 확인을 추가했다. 이전 콜백을 보관해 새 화면에 전달한 App.session 5개가 수정 전 실패→수정 후 통과했다. 표시 컴포넌트 두 개와 저장 I/O를 제어했으므로 자연 발생한 Phaser 경주를 포착한 근거는 아니다.
- **이야기 전역 단축키:** 기본 버튼/링크/편집 영역과 조합키/반복/IME/defaultPrevented를 제외했다. 타이틀 Enter가 장면을 함께 넘기지 않고, 제목의 일반 숫자·Enter 및 다음 버튼 Enter는 실제 브라우저에서 한 번만 진행한다.
- **폼 초점:** 명령 제출 후 선택 초기화로 비활성화된 버튼에서 초점이 사라졌다. FieldExam/PetalTraining/CaptainTrial은 같은 active 단계의 다음 턴에 첫 사용 가능한 라디오로 이동한다. 선택 자체는 실행하지 않는다. 초기/새 장면 제목과 실패/확인/완료 결과 초점은 유지한다. DOM 회귀 8개 추가, 폐광 2개 수정 전 실패, 수정 후 세 파일 36개 통과. 새 빌드 실입력 재검증도 통과했다.
- **전술 표적:** 실제 적 중앙 클릭의 CP/HP 불변과 좌상단 클릭의 반응을 재현했다. 조장/적 원의 hitArea 중심을 Shape displayOrigin에 맞췄다. 최종 빌드에서는 오프셋 0의 조장 선택·적 공격이 반응했다.
- **카메라 확대:** 실제 표적 공격 때 `this.ease is not a function` 두 번을 관찰했다. 설치된 Phaser Zoom 클래스의 진단에서 문자열 해석 차이를 확인해 실제 easing 함수를 쓰고 ZOOM_COMPLETE 뒤 복귀시킨다. 진단 stack은 브라우저 stack과 구분한다. 최종 4인전/재현전은 수집한 pageerror가 0이다.

## 자동 검사와 빌드

최종 **28파일·382개 검사**가 통과했다. 기준 356개에 App.session 5, OriginStory.keyboard 6, journeyVerification 6, App.flow 1, 세 폼 초점 8개가 추가됐다. TypeScript·전체 ESLint·프로덕션 빌드·Git 공백 검사도 통과했다.

App.flow는 실제 App·화면·리듀서·save/load와 IndexedDB 없는 jsdom LocalStorage로 폐광 선택부터(1턴 후 재마운트 포함) 첫 작전 방식 선택까지 통찰 경로를 진행한다. 앞선 7장면만 준비 시드이며 Canvas 물리 입력은 아니다. jsdom은 개발 의존성이다.

journeyVerification은 실제 규칙 API로 세 성향의 서장·6체험, 같은 성장의 4인/6인 전투, 엔진 패배·재시도·출전 당시 수치 고정·저장 실패·중복 정산을 확인한다. Map 기반 LocalStorage와 예외 주입을 사용한다. 저장 못 한 승리의 자동 복구를 확인한 것이 아니라 마지막 active 저장 유지와 보유한 유효 승리 재제출/재정산을 확인한 것이다.

최종 manifest의 playable 7개 진입점과 모든 참조 파일이 존재한다. 제작자/테스트/jsdom 청크는 배포에 없다. public **2,181파일·262,416,491바이트**와 dist 복사본의 SHA-256이 모두 일치하며, 단독 dist의 공개 파일도 복원됐다. 기존 Phaser 약 1.48MB 청크 경고는 남는다. 배포하지 않았다.

## 환경·증거·한계

사용자가 승인한 별도 Playwright/Edge 153.0.4234.32, 격리 `http://127.0.0.1:4409`와 독립 context를 사용했다. 원래 사용자 저장을 쓰지 않았다. 루트의 처음 새 게임에서 생성한 정상 체크포인트를 경계/대체/전투 사례로 복제했다. 그 이후 진행·승패·보상은 실제 입력으로 만들었다.

초기 CUA 4407은 7묶음 빌드여서 이번 수정 근거로 사용하지 않는다. 4408의 앞 5장면 준비+capital 선택 후 타이틀 Enter/저장 불변은 제한된 이전 근거다. CUA timeout, 디스크 고갈, 검증 스크립트의 선택자·측정 시점·초기 입력 실패는 제품 결함과 별도 기록한다.

디스크 고갈 때 사용자 수동 정리로 dist의 동일 생성 복사본 네 디렉터리가 제거됐다. 임시 서버는 같은 URL에 public 원본을 제공했다. 최종 재빌드는 공개 파일을 모두 복원했고 해시 대조를 통과했다. 따라서 초기 임시 패키지와 최종 완전한 dist를 구분한다.

원본 근거 파일 묶음: `native-root-steps.json`, `native-alternatives-{forms,river}-result.json`, `native-boundary-result.json` 및 `native-boundary-focus-*.json`, `native-battle-{tactical,action,four-tactical}-results.json`, `native-final-build-verification.json`, 최종 Vitest JSON. 사용자 출력 보고서에 각 원본과 화면을 함께 보존했다. 핵심 플로우와 발견된 결함은 처리됐으나, 실물 모바일/IME·모든 장비 조합·액션 승리 등 미수행 범위까지 통과로 확대하지 않는다.

원전 및 기존 `docs/source`, `world-bible-v3.1`, originStory/grandStory/battle 데이터, actionBattleRules/battleEngine/heroGrowth 규칙은 7묶음 기준과 같음을 확인했다. 원격 푸시·배포·3D 제작은 하지 않았다.
