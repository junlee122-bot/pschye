## 코드 읽기에서 찾은 입력 문제

`OriginStory.tsx`의 기존 전역 `keydown`은 선택이 있는 장면에서 Enter가 어디서 발생했는지 확인하지 않고 진행을 호출했다. 따라서 ‘타이틀’ 버튼에 초점을 둔 Enter가 기본 버튼 활성화 외에 장면 진행도 요청하는 경로가 있었다. 숫자 선택도 조합키·반복·편집 영역을 구분하지 않았다. 이는 코드 경로로 확인한 P1 입력 충돌이며, 이 문서 작성 시점에 실제 브라우저 재현을 완료했다고 표시하지 않는다.

수정은 기본 버튼·링크·입력·선택·텍스트 영역·편집 가능한 영역 내부, 조합키·반복·IME·이미 처리된 이벤트를 전역 단축키에서 제외한다. 제목·배경의 순수 Enter와 1~3은 유지하고 처리한 단축키만 기본 동작을 막는다. 신규 `OriginStory.keyboard.test.tsx`의 **ReactDOM 실제 마운트·초점·버블링 이벤트·화면 해제 6개가 jsdom 26.1.0에서 통과**했고, 소유 컴포넌트·테스트 ESLint도 통과했다. jsdom은 키 입력의 기본 클릭을 합성하지 않으므로, 테스트의 별도 클릭 확인은 브라우저 키보드 완주의 증거가 아니다.

App의 조장 선발·폐광·수련·정식 전투에 있던 슬롯 세대 확인을 초기 이야기 선택과 마을 이동·구출에도 적용했다. 구출 행동은 현재 시도와 동작을, 재시도·귀환은 현재 시도를 추가로 대조한다. `App.session.test.tsx`에서 이전 콜백을 보관해 실제 App에 전달한 5개 검사가 수정 전 모두 실패했고, 수정 후 모두 통과했다. 슬롯 전환 뒤 좌표·선택 변경, 같은 슬롯 초기화 뒤 이전 선택 보상 적용, 같은 렌더의 중복 행동, 실제 동작 소진 후 재시도에 이전 행동이 들어가는 경우다. 두 마을 표시 컴포넌트와 저장 I/O를 제어했으며, 자연스럽게 발생한 Phaser 이벤트 경주를 실제 브라우저에서 재현했다는 뜻은 아니다.

첫 작전은 `originStory.completed` 뒤 CampaignHub로 연결되며, 선택·라온 포함 편성·미정산 작전 여부를 확인한 후 출전한다. `App.flow.test.tsx`는 실제 App·화면·save/load와 IndexedDB가 없는 jsdom의 LocalStorage로 폐광 도중 재마운트 복구부터 마루 수련·세 대결·후일담·선서·입단·첫 작전 방식 선택까지 통찰 한 경로의 DOM 흐름을 통과했다. 화면·리듀서·저장 모의 객체는 없으며, 앞선 7장면만 준비 시드다. 이미지·Canvas·실제 브라우저 입력과 렌더링, 다른 성향의 UI·IndexedDB 경로는 이 검사의 범위 밖이다.

`journeyVerification.test.ts` 6개는 실제 규칙 API로 세 성향의 모든 서장 장면과 6개 체험을 진행·저장하고, 같은 성장 조건의 4인·6인 출격조로 첫 전투 6회 승리와 엔진이 만든 패배를 확인했다. 기존 출전 수치 고정·재시도·포기 후 새 출전도 확인했다. 저장은 IndexedDB 없이 Map 기반 localStorage 모의를 사용하며 setItem 예외로 실패를 주입했다. 승리 체크포인트 저장 실패에서는 마지막 active 저장이 유지됨을 확인한 후 보유한 유효 승리 상태를 재제출하여 정산했다. 정산 저장 실패에서는 저장된 승리를 다시 읽어 중복 없이 정산했다. 저장하지 못한 승리를 자동 복원했다고 해석하지 않는다. 해당 검사는 결정적 엔진/API 실행이며 브라우저 전투 조작은 아니다.

## 실제 브라우저 전체 여정의 현재 한계

새 4406 진단 페이지에서 실제 마우스·Tab/Enter 입력을 확인한 뒤, 4407의 기존 7묶음 배포본을 새 저장으로 시작했다. 마을 지도·390px 이동 조작까지 확인했지만 첫 대화 전에 입력 시간 초과가 발생했다. 같은 origin의 가벼운 진단 페이지는 정상 작동했고, 게임에 다시 접속해 한 입력과 다음 호출의 관찰을 분리했을 때 9개 이동·관찰 쌍이 성공했다. 10번째 입력 후에는 화면 상태 읽기가 시간 초과됐다. 이 대조만으로 원인을 Phaser·앱 부하·저장 처리·도구 중 하나로 확정하지 않는다.

최종 소스를 별도로 빌드한 4408에서는 앞선 5장면의 완료 ID를 준비하고 실제 선택 API로 `capital-gate / identify-poison`을 적용했다. 실제 App의 ‘타이틀’ 버튼에 Enter를 입력한 뒤 도구는 시간 초과를 보고했으나, 한 차례 재연결 후 타이틀 화면과 실제 save/load 재읽기를 확인했다. 장면 ID·점수 4·선택·완료 장면 ID와 관계·성장·자원 등을 포함한 비교 요약이 모두 유지됐다. 이는 준비한 한 텍스트 장면에서 수정 후 결과를 관찰한 근거이며, 앞선 장면의 플레이나 전체 여정은 아니다. 320px 타이틀·저장 슬롯의 접근성 트리는 읽었지만 스크린샷이 시간 초과되어 폭·시각 배치의 통과로 기록하지 않는다.

새 게임부터 첫 공식 전투까지의 실제 연속 완주, 남은 성향별 직접 플레이, 정식 전투 승패·정산의 직접 조작, 320px·터치 취소 등은 완료로 처리하지 않는다. 이번 코드 수정과 자동/DOM 검증 완료를 전체 수동 검증 완료나 3D 제작 준비 완료로 확대하지 않는다. 원래 사용자 저장에는 접근하지 않았고, 각 격리 서버·화면 크기 정리를 별도 기록했다.

최종 기록에는 빌드/커밋, 테스트 origin·슬롯, 시작 상태가 새 게임인지 시드인지, 실제 입력과 기대·관찰 상태, 저장 전후 비교, 화면 경로, 도구 오류를 남긴다. CUA 입력·연결 실패로 동작 결과를 읽지 못하면 기능 실패나 성공으로 판정하지 않는다. 최근 로그 일부가 비어 있어도 전체 무오류라고 기록하지 않는다.
