# Meng To Skills × 라온제나 통합 설계

## 1. 결론

두 참고 자료에서 라온제나가 가져와야 할 핵심은 새 그래픽 효과 하나가 아니라 **게임을 계속 확장해도 품질이 무너지지 않는 제작 운영체계**다.

- 하나의 완결된 플레이 루프를 먼저 증명한다.
- 스토리, 전투, 적, 장소, 자산을 안정된 데이터 계약으로 분리한다.
- 실제 배포된 자산과 미래 경로·플레이스홀더를 구분한다.
- 적과 캐릭터의 행동을 번호가 있는 의미 단위 무브셋으로 검수한다.
- 어려운 상태를 긴 플레이 없이 즉시 재현하는 검수 화면을 만든다.
- 시각 자료는 게임 공간의 참고 자료로 쓰고 충돌·길찾기·판정은 별도 데이터로 만든다.

라온제나는 순수 아이소메트릭 ARPG가 아니라 **라온 고정 시점의 스토리텔링 RPG**다. 따라서 Meng To의 구조를 그대로 복제하지 않고, `마을 탐색 → 대화와 선택 → 실전 전투 → 관계와 기록 변화 → 다음 장면`이라는 라온제나의 루프에 맞춰 적용한다.

## 2. 참고 자료에서 확인한 핵심

### MengTo/Skills

저장소는 프롬프트를 일회성 문장이 아니라 버전 관리되는 제작 자산으로 보고, 명시적인 절차와 검증 기준을 `SKILL.md`에 보존한다.

게임 제작 항목에서는 다음 원칙이 특히 중요하다.

1. 메뉴부터 보상과 다음 진행까지 이어지는 하나의 수직 조각을 먼저 완성한다.
2. authored content와 runtime state를 분리한다.
3. 전투 행동은 준비·판정·회복 시간과 취소 조건을 명시한다.
4. 레벨 장식, 충돌, 길찾기, 전투 구역을 서로 다른 층으로 둔다.
5. 적의 인지, 의도, 이동, 판정, 표현을 분리한다.
6. 생성 2D, 절차형 모델, 외부 모델, 플레이스홀더의 출처를 정직하게 기록한다.
7. 실제 카메라 거리와 모바일 환경에서 검증한다.

### Threads 게시물

게시물은 저장소의 가치를 다음 세 가지로 요약한다.

- 게임 제작 전용 절차서가 카메라, 전투, 적 AI, 인벤토리, VFX, 최적화, 플레이테스트를 단계별로 통제한다.
- 자산 원장은 실제로 들어온 파일과 주소만 선언된 파일을 구분한다.
- 외부 적 모델이 없어도 적을 코드로 만들 수 있지만, 이를 수입 모델로 포장하지 않고 무브셋과 출처를 검수 화면에서 공개한다.

이 원칙은 현재 라온제나의 대규모 생성 이미지와 516개 장면을 관리하는 데 직접적인 가치가 있다.

## 4. 도입할 제작 체계

### 4.1 라온 수직 조각 계약

첫 번째 품질 기준은 아래 흐름을 저장·재시도까지 끊김 없이 플레이할 수 있는지다.

1. 변방 마을 새벽에 라온으로 이동한다.
2. 카즈린과 대화하고 첫 성향 선택을 한다.
3. 카인의 대련에 개입해 이동·회피·가드·기본 공격을 배운다.
4. 수로 사건에서 탐색과 비전투 선택을 경험한다.
5. 프시케 지원 여부를 선택하고 마을 관계가 변한다.
6. 회색 교각 호송에서 전술 또는 직접 조작 전투를 수행한다.
7. 보상, 관계 기억, 세계 기록, 다음 임무가 원자적으로 저장된다.

새 시스템은 이 조각에서 플레이 증거를 만든 뒤 다음 장으로 확장한다.

### 4.2 장면 레시피

516개 장면을 모두 같은 대화 UI로 처리하지 않는다. 각 장면에 다음 중 2~4개의 플레이 동사를 배정한다.

- `move`: 장소 안에서 목표까지 이동
- `observe`: 흔적·인물·지형 조사
- `talk`: 대화와 질문
- `choose`: 라온의 연민·통찰·결의 선택
- `train`: 기술 입력과 숙련
- `fight`: 액션 또는 전술 전투
- `protect`: 민간인·동료·물자 보호
- `escape`: 제한 시간·추격·퇴로 확보
- `report`: 라온의 언어로 사건을 기록
- `remember`: 과거 장면을 현재 의미로 재해석

장면 데이터는 `hook → exploration → pressure → choice → consequence → memory` 순서의 짧은 비트로 구성한다. 모든 장면이 전투를 요구하지 않으며, 선택 결과는 즉시 수치보다 이후 인물의 행동과 기록 문장으로 먼저 보여준다.

### 4.3 장소 층 분리와 디렉터 맵

각 장소는 다음 층을 독립적으로 가진다.

1. `visual`: 배경, 건물, 소품, 조명
2. `collision`: 단순 충돌 도형
3. `navigation`: 라온과 NPC의 이동 가능 영역
4. `anchors`: 대화, 조사, 스폰, 퇴로, 체크포인트
5. `encounter`: 적 구성, 진입·종료·리셋 조건
6. `persistence`: 발견, 파괴, 구조, 재방문 상태

개발자용 디렉터 맵은 실제 장소 데이터를 읽되, 편집 결과를 즉시 본편에 쓰지 않는다.

`production source → editor document → isolated draft → validated export → reviewed integration`

첫 대상은 `src/data/village.ts`다. 주민, 상호작용 지점, 소품, 랜드마크를 화면에서 선택하고 좌표·반경·일정을 확인하며, 변경안은 버전이 있는 JSON 초안으로만 내보낸다.

### 4.4 전투 행동 계약

현재 전술 전투와 액션 전투가 같은 규칙 언어를 공유하도록 모든 기술을 다음 데이터로 확장한다.

| 필드 | 의미 |
|---|---|
| `startupMs` | 공격 예고와 준비 시간 |
| `activeMs` | 실제 판정이 발생하는 시간 |
| `recoveryMs` | 다음 행동 전 빈틈 |
| `cancelRules` | 회피·가드·피격으로 취소 가능한 단계 |
| `range` / `angle` | 유효 거리와 방향 |
| `contactShape` | 검격·창끝·투사체·범위 판정 |
| `posture` | 방어 자세에 주는 압박 |
| `cooldown` | 재사용 제한 |
| `feedbackHooks` | VFX·음향·카메라·UI 사건 ID |

판정이 먼저 확정되고 애니메이션과 VFX는 그 결과를 표현한다. 플레이어가 보이는 동작을 추측해 맞는 구조를 피한다.

### 4.5 라온 전투의 재미 구조

라온의 전투는 많은 기술을 난사하는 방식보다 **검로를 읽고 한 번의 연결을 완성하는 방식**으로 차별화한다.

1. `읽기`: 적의 준비 동작·사선·회복 방향을 본다.
2. `응답`: 간격 이동, 회피, 흘리기, 동료 명령 중 하나를 고른다.
3. `연결`: 성공한 응답이 꽃잎 스택과 집중 연계를 만든다.
4. `결단`: 안전한 이탈, 동료 보호, 16꽃잎 돌파 중 하나로 마무리한다.

방어 수단의 역할도 겹치지 않게 한다.

- 이동: 위험 구역에서 벗어난다.
- 회피: 짧은 공격을 통과하지만 자세를 잃는다.
- 흘리기: 정확한 방향과 타이밍으로 집중을 얻는다.
- 동료 명령: 라온의 위험을 팀 전체의 위치 결정으로 바꾼다.
- 중단 공격: 긴 준비 동작을 끊지만 실패하면 큰 빈틈을 만든다.

### 4.6 적 정의와 번호형 무브셋

적마다 최소한 다음 상태를 정의한다.

`idle → investigate → pursue → reposition → windup → attack → recover → stagger → defeated`

체시 공중 저격수의 첫 검수 무브셋은 다음처럼 구성한다.

1. 공중 대기
2. 표적 탐색
3. 사선 확보
4. 고도 재배치
5. 조준 예고
6. 정밀 사격
7. 시야 봉쇄탄
8. 피격·비틀거림
9. 추락·패배

각 행동은 번호, 시간, 발동 조건, 대응법, 사용 자산, VFX·음향 훅을 갖는다. 외부 모델이 없으면 Phaser 도형·절차형 실루엣·2D 파츠로 만들 수 있으나 자산 원장에는 `procedural-runtime`으로 표시한다.

### 4.7 자산 원장과 검수실

이번 작업에서 `tools/asset-ledger-audit.mjs`를 추가했다.

- `public/art`의 실제 배포 파일을 전수 조사한다.
- 소스·문서의 정적 선언과 비교한다.
- 제공 원본, 생성 스토리, 생성 장소, 생성 캐릭터, 프로젝트 자산으로 분류한다.
- 파일 크기와 SHA-256을 기록한다.
- 선언됐지만 누락된 파일을 분리한다.
- `artifacts/asset-ledger/ledger.json`과 `ledger.md`를 생성한다.

다음 단계의 인게임 개발자 검수실은 아래 화면을 제공한다.

- 자산 카드: 실제 이미지, 형식, 용량, 출처, 사용처
- `shipped` / `declared only` / `fallback` 상태
- 캐릭터별 시대·표정·전투·부상 바리에이션
- 적별 절차형 또는 외부 모델 출처
- 번호형 무브셋 재생
- 예고·유효·회복 프레임 정지
- 실제 게임 카메라 거리 미리보기
- 모바일·저사양·모션 감소 모드

### 4.8 기억 아카이브의 시네마틱 스토리텔링

Meng To의 스크롤 스토리텔링은 본편 이동 조작이 아니라 연대기와 기억 복원 화면에 제한해서 쓴다.

- 한 화면에 하나의 시기와 하나의 감정 중심만 둔다.
- 스크롤을 가로채지 않고 진행률에 맞춰 이미지·문장·기록 차이를 드러낸다.
- 제국 공식 기록과 실제 기록을 같은 장면에서 겹쳐 보여준다.
- 해찬편 진입은 현재의 지팡이 소리에서 과거의 발걸음으로 연결한다.
- `prefers-reduced-motion`에서는 모든 장면을 정적인 카드와 텍스트로 제공한다.

시각 방향은 제공된 설정화와 잘 맞는 `warm paper + technical frame`을 유지한다. 검은 바깥 프레임, 따뜻한 종이 면, 얇은 금속선, 절제된 금색·보라색 강조를 사용하며 일반적인 유리형 SaaS UI로 바꾸지 않는다.

| 원본 데모의 시각 디자인 | 그대로 복사하지 않음 | 설정화의 종이 기록물 문법으로 재설계 |

## 6. 구현 우선순위

### P0 — 제작 진실성

- 완료: 전체 자산 원장 생성 도구
- 다음: 자산별 명시 출처·생성 프롬프트·라이선스·사용처 입력
- 다음: `declared only`, `fallback`, `review only` 상태를 UI에 표시

### P1 — 첫 마을 수직 조각

- `village.ts`를 시각·충돌·앵커·일정 데이터로 분리
- 디렉터 맵 초안
- 라온 이동·조사·대화·대련·수로·지원·출발의 완전한 저장 루프
- 마을 주민이 선택 이후 다른 위치와 대사를 갖도록 일정·기억 연결

### P2 — 전투 계약 통합

- 기술과 적 행동의 준비·유효·회복 데이터 추가
- 전술 모드와 직접 조작 모드가 같은 판정 사건 사용
- 체시 저격수 9개 무브셋 검수 화면
- 공격 예고·회피·흘리기·중단·집중 연계 튜토리얼

### P3 — 콘텐츠 제작 도구

- 장소 디렉터 맵
- 장면 레시피 편집·검증
- 적·캐릭터 자산 검수실

## 7. 품질 통과 기준

기능은 다음 조건을 모두 통과해야 완료로 본다.

1. 새 게임, 이어하기, 패배 후 재시도, 장면 전환이 같은 저장 계약을 사용한다.
2. 전투 행동의 예고·판정·피드백이 화면과 내부 상태에서 일치한다.
3. 적의 모든 행동을 검수 화면에서 즉시 재현할 수 있다.
4. 장소 장식에서 충돌과 임무 구역을 추측하지 않는다.
5. 모든 자산이 실제 배포, 선언 전용, 플레이스홀더, 생성, 제공 원본 중 하나로 분류된다.
6. 데스크톱·모바일·모션 감소에서 핵심 루프가 완주된다.
7. 자동 테스트 결과와 실제 브라우저 플레이 증거를 함께 남긴다.
