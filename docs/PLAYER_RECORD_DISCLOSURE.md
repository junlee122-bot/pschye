# 플레이어 기록 공개 기준

2026-09-12 · 두 번째 작업 묶음

## 게임 기록과 제작 원장

일반 게임은 `storyAccess.ts`가 만든 진행별 데이터를 사용한다. `Chronicle`은 실제 완료한 서장과 작전의 기록, `Codex`와 `Roster`는 현재 알 수 있는 인물 소개, `PlayerArchive`는 같은 범위의 이미지로 구성한다. 검색과 상세창도 이 데이터 안에서만 선택한다. 원전의 후반 진실·인물 최종 성장·미정 결말을 통째로 전달하지 않는다.

전체 StoryAtlas·LocationAtlas·기수와 역사·인물 원장·설정화·3D 검수는 개발 서버의 `/?workspace=author`로 들어가는 제작자 자료실에 보존했다. 전체 스포일러 안내를 확인해야 열리며, 이 화면은 캠페인 저장 로직을 실행하지 않는다. 프로덕션에서는 같은 URL을 입력해도 제작자 화면으로 전환되지 않는다. 일반 게임의 `?section=archive&archive=models`도 공개 화첩만 표시한다.

이는 플레이 경험의 공개 순서를 지키는 UI 규칙이다. 브라우저에 전달되는 모든 원본 데이터·정적 파일을 비밀로 보관하는 보안 장치는 아니다.

## 해금 조건

| 기록 | 공개 조건 |
| --- | --- |
| 라온의 초기 소개 | 새 여정부터 |
| 서장 회고와 이미지 | 해당 장면 완료. 저장된 선택의 결과만 회고에 포함 |
| 만난 사람 | 완료 장면의 화자. 입단 완료 시 제7기 동료와 만난 지도자 소개 |
| 다음 작전 브리핑 | 서장 완료 및 해당 작전의 선행 임무 완료 |
| 완료 작전 회고 | `completedMissions`에 해당 임무가 있음 |
| 특정 현장 증언 | 완료한 임무에 `witness-<missionId>` 기록이 있음 |
| 인물의 증언 탭 | 해당 인물이 이끌어 낸 현장 증언만. 인물의 원본 `hiddenTruth` 전체를 열지 않음 |
| 육성·본부·전선·활동 | 입단 완료 후. 직접 section URL에도 같은 경계 적용 |
| 미구현 후반 서사·결말 | 일반 게임에서 미공개. 제작 원장에서만 열람 |

알 수 없는 장면·임무·증언 ID는 공개 근거로 사용하지 않는다. 레벨, 보관소 레벨, 날짜나 단순 클리어 수로 후반 인물 원장을 해금하지 않는다. 슬롯 전환이나 진행 초기화 때 상세 선택도 현재 허용된 데이터에서 다시 찾는다.

## 전투 증언 저장

새 `witness-*` 토큰은 다음 조건을 모두 만족할 때만 발급한다.

1. 임무에 증언 조건이 있다.
2. 전달된 전투 상태의 `missionId`가 임무와 같다.
3. 전투 결과가 `victory`다.
4. 전투 중 조건부 증언이 실제 발동하여 `revelationTriggered === true`다.

첫 클리어와 재도전 모두 적용한다. 이미 완료한 임무에서 증언만 새로 확보할 수 있으며 경험치·물자·날짜 등 최초 보상을 다시 지급하지 않는다. 이미 있는 토큰과 로그를 중복 추가하지 않는다.

이전 v10은 임무만 완료해도 `truth-*`를 지급해 실제 발동 여부를 판별할 수 없었다. 기존 토큰과 클리어·등급·보상은 보존하지만, 새 플레이어 증언의 근거로 간주하지 않는다. 해당 작전을 재도전하여 실제 증언을 확보하면 열린다. 저장 형식 버전이나 필드는 추가하지 않는다.

## 정사 판정

제작 원장의 `canonStatus`와 `canonNotice`는 서사의 근거 상태다. 플레이어의 진행 해금 상태와는 별개다. 네 상태와 카인·라미편의 근거는 [CANON_STATUS.md](CANON_STATUS.md)를 따른다. 각색 초안을 원전 또는 사용자 확정으로 승격시키지 않는다.

## 검증 범위

순수 공개 정책, 실제 React 정적 마크업, 최초/재도전 증언 지급, 마을 이벤트 동기화의 회귀 검사를 추가했다. 정적 렌더 검사는 실제 포인터·Phaser 프레임·브라우저 슬롯 전환을 대신하지 않는다. 실제 브라우저 검증 결과와 한계는 작업 완료 보고서에 별도로 기록한다.
