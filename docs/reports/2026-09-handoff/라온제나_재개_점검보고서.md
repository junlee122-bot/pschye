## 이어받을 제작 목표

이전 사용자 요구의 최종 방향은 **라온의 시점으로 마을에서 출발해 선택·동료 관계·프시케 입단·탐험·전투를 경험하는, 이야기 중심의 3D 액션 어드벤처**다. 게임을 젤다처럼 확장하고, 단순 도형이 아닌 실제 캐릭터 외형을 갖추길 요청했다.

현재의 세계관 핵심은 지워진 구원의 진실과 다음 세대의 선택이다. 공식 역사와 실제 역사가 다르며, 독자가 진실을 알게 되는 순서가 중요하다. 다만 이전 AI가 마지막에 제공한 세계관 해설 전체를 확정 정사로 취급하면 안 된다. 원전·사용자 확정·각색안을 다시 구분해야 한다.

## 우선 해결할 문제

아래 파일·줄 표기는 모두 위 원본 작업 폴더를 기준으로 한다. P1은 후속 제작 전에 해결할 중요한 오류, P2는 사용성·검증 기준 보완이다.

### 1. [P1] 액션 전투가 RPG 성장과 선택을 반영하지 않는다

`src/components/RaonActionBattle.tsx:39`의 Phaser 입력 모델에는 영웅 성장치, 성향, 전쟁 압박, 유대가 없다. `:153`의 HP는 220 기반이며 `:314`, `:331`의 공격력도 상수로 계산된다. `:362`의 동료 명령은 하도리·카즈린·레오의 실제 편성 여부를 검사하지 않는다.

특수 포격·재은폐·중립 목표 피해·시간 피해 등 작전별 규칙은 전술 엔진에는 있지만 액션 모드에서는 실제 처리되지 않고 규칙 라벨만 표시된다(`:672`).

**영향:** 장비·레벨·편성·선택을 바꿔도 액션 플레이에 기대한 변화가 생기지 않는다. 두 전투 모드가 같은 캠페인 규칙을 공유하도록 연결해야 한다. 근거는 정적 데이터 흐름 분석이며 이번 브라우저에서 전투까지 재현한 것은 아니다.

### 2. [P1] 기술점을 소비해도 체능 노드 효과가 없다 — 직접 재현

`src/components/Roster.tsx:15`는 기술 위력·사기 강화 등을 설명하지만, `src/game/progression.ts:556`의 구매 함수는 기술점과 노드 ID만 바꾼다. `:827`의 전투 영웅 생성에는 해금 노드 효과가 없다.

실제 함수 호출 결과:

```text
새 프로필 → 라온 fieldcraft 구매
기술점: 1 → 0
해금: foundation, fieldcraft
buildProgressedHeroes 구매 전후: 완전히 동일
```

재현 결과는 같은 폴더의 `reproduction-results.json`에 저장했다. 노드 효과를 정의하고 전투 능력치·규칙에 적용해야 한다.

### 3. [P1] 저장 백업의 복구 경로가 연결되지 않았다

`src/game/persistence.ts:56`의 IndexedDB 복구 함수는 다른 소스에서 호출되지 않는다. `src/game/progression.ts:350`은 LocalStorage만 읽고 JSON 오류나 부재 시 새 여정을 반환한다. `src/App.tsx:80`의 자동 저장은 그 새 여정을 IndexedDB에도 다시 기록한다.

**영향:** LocalStorage 슬롯만 손상되거나 삭제됐을 때 정상 IndexedDB 백업이 있어도 이를 복구하지 않고 새 프로필로 덮어쓸 수 있다. 실제 사용자 저장 데이터를 손상시키는 실험은 하지 않았다. 로드 실패→백업 검사→복구/새 게임 선택→자동 저장 순서로 고쳐야 한다.

### 4. [P1] 초반 플레이어에게 후반 반전이 노출된다

`src/App.tsx:302`의 Chronicle에는 진행 상태가 전달되지 않는다. `src/components/Chronicle.tsx:31`은 전체 StoryAtlas, `:49`는 생존자 기록 전체를 제공한다. `StoryAtlas.tsx:79`, `:183`은 전체 516비트 검색과 마지막 사가까지의 선택을 허용한다.

`src/components/CharacterDetail.tsx:13`도 7기·5기 진실을 처음부터 공개한다. 예를 들어 `src/data/lore.ts:112`의 레오 기록에는 진훤 사망·나비 폭주가 있다.

**영향:** 공식 역사를 믿게 한 뒤 해찬편에서 의미를 뒤집는 공개 순서가 무너진다. 제작자용 전체 원장과 플레이어용 도감을 구분하고 사건별 해금을 적용해야 한다. 이번 브라우저에서는 해당 도감까지 조작하지 못했으며 소스 조건으로 확인했다.

### 5. [P1] 정사 판정과 확장 서사에 충돌이 있다

**카인 결말:** `docs/CANON_STATUS.md:44`는 사용자 확정 없는 보완을 설계안으로 두고 `:48`에서 카인 결말을 미정으로 남긴다. 반면 `docs/GRAND_STORY_BLUEPRINT.md:66`은 생존·장기 책임을 정사 보호선으로 적고, `src/data/grandStory.ts:833`은 오른손 감각 상실까지 단정한다. 원전과 대화에서 별도 확정 근거를 찾아 연결하기 전에는 후자를 각색 초안으로 다뤄야 한다.

**라미편 연표:** `src/data/grandStory.ts:858`은 대전쟁 120년 전 라미 유년기에 데닌 노동자를 배치하고, `:888`은 이미 날개·사능을 잃은 데닌을 묘사한다. 그런데 `:928`은 데닌 탄생의 최초 빛을 대전쟁 90년 전으로 둔다. 원전 `docs/source/world-bible-v3.1.md:71`은 빛→날개·사능 상실 순서다. 현재 확장 연표에는 탄생 이전의 데닌이 등장한다.

### 6. [P2] 가능한 명령이 없는데 턴 종료를 막는 상태 — 엔진 상태 직접 재현

`src/components/BattleScreen.tsx:192`, `:280`은 CP와 미행동 영웅이 남으면 턴 종료를 거부한다. 사용 가능한 기술이 있는지는 확인하지 않는다.

재현: 기록 난이도의 첫 작전, 라온·카즈린·카인·레오 편성, 고레벨 라온의 광역기 후 카즈린·레오 방벽 사용. CP 1, 사기 46, 미행동 카인만 남고 유일한 적은 은폐 저격수가 된다. 사용 가능한 추천 행동은 없다. 이때 UI 종료 조건은 진행을 막는다. 행동 취소로 순서를 바꾸는 우회는 가능하므로 회복 불가능한 막힘은 아니다.

명령 가용성을 기준으로 종료를 허용하거나 명시적인 행동 포기를 제공해야 한다.

### 7. [P2] 마을 대화 버튼의 접근 상태가 어긋날 가능성

`src/components/VillageAdventure.tsx:429`에서 이동을 700ms 주기로 저장하고 `:451`에서 모델이 바뀔 때 접근 상태를 false로 초기화한다. Phaser는 반경 진입/이탈처럼 상태가 바뀔 때만 접근 이벤트를 발행한다(`:350`). 따라서 NPC 근처에서 이동 후 멈추면 대화 버튼이 비활성으로 남을 수 있다. E키는 별도 경로가 있어 터치 조작에서 특히 확인할 필요가 있다.

**이 항목은 정적 분석에 따른 재현 후보다. 이번 브라우저 검사에서는 직접 재현하지 못했다.**

1. **원본 보존과 기준점 마련:** 소스·원전·실제 사용할 자산을 구분하고 Git 첫 커밋을 만들 준비. 대용량 도구·임시 파일·비밀키가 섞이지 않도록 업로드 범위를 정리한다.
2. **정사 표 고정:** 원전 근거, 사용자 확정, 각색 초안, 미정의 네 상태로 기록. 카인 결말과 라미 연표를 먼저 정리한다.
3. **진행 안정화:** 저장 복구, 체능 효과, 액션 성장·편성 반영, 전술 턴 종료, 스포일러 해금을 연결한다.
4. **첫 마을 한 구간을 완성:** 이동→대화→선택→소규모 전투→귀환 변화→저장/재개를 실제 플레이로 끝까지 검증한다.
5. **3D 본편의 첫 구간 제작:** 라온 한 명, 마을 한 곳, 연결 길, 소형 던전이라는 기존 로드맵 범위에서 3인칭 이동·카메라·상호작용을 먼저 구현한다. 검수용 모델을 플레이어 캐릭터로 연결하고 실제 엔진에서 검수한다.

**다음 착수점은 ‘진행 안정화와 정사 정리’가 적절하다. 현재 축적된 설정·미술을 실제 플레이 경험에 연결하는 작업이 가장 우선이다.**
