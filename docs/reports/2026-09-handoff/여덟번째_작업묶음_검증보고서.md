# 라온제나 여덟 번째 작업 묶음 검증보고서

2026-09-15 · 기존 2D 여정의 진행·저장·입력 검증

**8묶음의 핵심 여정 검증을 마쳤다.** 새 게임에서 서장 15개 장면·입단·첫 작전 준비까지 실제 입력으로 진행했고, 4인/6인 전술전 승리와 액션전 패배·재시도를 확인했다. 슬롯 입력 격리와 이야기 단축키에 이어, 실제 플레이에서 드러난 폼 초점·전술 표적 클릭·확대 효과 오류를 수정했다. 전체 28파일·382개 자동 검사, TypeScript·전체 ESLint·프로덕션 빌드가 통과했다.

새 빌드 `index-DEx4xGQm.js`에서 중앙 클릭이 정상 반응하고, 4인 승리·재현 승리 중 수집한 페이지 오류는 0이었다. 세 폼도 직접 초점을 지정하지 않고 Tab·방향키·Space·Enter만으로 여러 턴과 결과 확인을 이어갔다. 실물 모바일/IME와 모든 장비 조합의 UI 순회는 아래 제한으로 남긴다. 다음 작업은 **9묶음: 3D 조작 기반·라온**이다.

## 수정 내용

1. **이전 화면의 입력이 다른 저장에 적용되는 경계.** 슬롯을 바꾸거나 같은 슬롯에서 새 여정을 시작한 뒤 이전 이야기 선택·마을 좌표·구출 입력이 새 저장에 들어가지 않도록 슬롯 세대, 시도, 동작 번호를 확인한다. 이전 콜백을 전달한 App 회귀 5개가 수정 전 실패하고 수정 후 통과했다.
2. **이야기 단축키의 충돌.** 타이틀·다음 버튼의 Enter가 전역 장면 진행까지 일으키지 않게 했다. 편집/버튼 영역, 수정키, 반복, IME 입력을 전역 단축키에서 제외한다. 실제 제목의 숫자·Enter와 다음 버튼 Enter가 한 번씩만 진행하는 것도 확인했다.
3. **명령 제출 후 초점 손실.** 폐광·마루 수련·조장 대결은 제출 버튼이 비활성화될 때 초점이 빠질 수 있었다. 다음 턴의 첫 사용 가능한 라디오로 초점을 돌리고, 완료·실패 시 결과 영역 초점을 유지한다. 추가 DOM 회귀 8개 중 폐광의 문제를 재현한 2개는 수정 전 실패했다.
4. **전술 표적의 중앙 클릭 불응.** 원형 Shape의 표시 원점과 입력 원의 중심을 맞췄다. 수정 전에는 적 중앙을 눌러도 CP·HP가 바뀌지 않고 원 안의 좌상단을 눌러야 공격됐다. 조장 선택 원에도 같은 보정을 적용했다.
5. **공격 시 확대 효과 오류.** 카메라가 해석하지 못하는 easing 문자열 때문에 `this.ease is not a function`이 발생했다. Phaser의 실제 easing 함수를 전달하고 확대 완료 후 원래 배율로 돌아오게 했다.

원전·기존 이야기 데이터·정식 전투 및 성장 규칙은 변경하지 않았다. jsdom은 개발 의존성으로만 사용한다.

새 게임 여정은 도구 및 디스크 부족 때문에 중단됐다가 **그 여정에서 실제로 저장한 체크포인트로 재개**했다. 한 번도 끊기지 않은 단일 세션은 아니다. 대체 성향·경계·전투 검증은 이 정상 체크포인트를 독립 context에 복제했으며, 복제 이전 구간을 각 사례의 새 플레이로 세지 않는다. 진행·승패·보상을 직접 주입하지 않았다.

브라우저는 사용자 승인에 따른 별도 Playwright/Edge 153.0.4234.32이고, origin은 `http://127.0.0.1:4409`이다. 원래 사용자 저장을 사용하지 않았다. 초기 CUA 4407은 7묶음 빌드였고, 4408의 준비 장면 Enter 검증과 도구 timeout은 이전 기록으로 보존했다.

## 자동 검사의 범위

기존 356개에서 이번 묶음의 입력 격리 5, 이야기 키보드 6, 규칙 통합 6, 실제 App DOM 흐름 1, 폼 초점 8개가 추가돼 **382개**가 됐다.

- 규칙 통합은 실제 게임 규칙 API로 세 성향의 전체 서장·체험, 같은 성장의 4인/6인 승리, 패배·재시도·출전 수치 고정·중복 정산을 확인한다. 브라우저 전투 조작과 구분한다.
- App DOM 흐름은 통찰 경로이며 폐광 선택부터 첫 작전 방식 선택까지 실제 화면·리듀서·LocalStorage를 쓴다. 폐광 1턴 뒤 재마운트 복구를 포함한다. 앞선 7장면은 명시적 준비 시드이고 jsdom에는 IndexedDB·Canvas 물리 입력이 없다.
- 콜백 격리 검사는 보관한 이전 콜백을 명시적으로 전달한다. 자연 발생한 Phaser 이벤트 경주를 포착했다는 뜻이 아니다.
- 저장 장애의 자동 검사와 실제 브라우저 검사는 쓰기 API 예외를 주입했다. 실제 디스크 고갈과 구분하며, 저장하지 못한 승리를 자동 복구한다고 주장하지 않는다.

## 남는 검증 범위

실물 모바일 장치에서 OS 터치 취소와 IME 조합 입력은 수행하지 않았다. 이번 길게 누르기/놓기는 mouse pointer, 취소는 합성 pointercancel이며, 실제 touchscreen으로는 대화 열기를 확인했다. 액션전 승리는 이번 새 브라우저 실행의 범위가 아니다. 성장·장비 변경 후 기존 출전 수치 유지의 전체 조합은 자동 규칙 검사 근거이며, 모든 조합을 UI로 순회하지 않았다.

제품 오류, 검증 스크립트의 선택자/측정 시점 오류, CUA 연결·디스크 고갈은 별도 기록했다. 수정 전 전술전에는 실제 런타임 오류 2회가 있었으므로 전체 검증 기간을 ‘브라우저 오류 0’으로 요약하지 않는다.
