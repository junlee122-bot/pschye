# 라온제나 일곱 번째 작업 묶음 보고서

2026-09-15 · 조장 선발전·입단

**카인 공방 → 카즈린 연속 공방 → 하도리 한 방 패배 → 의무동 대화 → 입단 → 첫 작전 준비**를 기존 서장에 연결했다. 16개 파일을 로컬 커밋으로 보존했다. 전체 **356개 테스트·타입 검사·린트·프로덕션 빌드가 통과**했다.

## 플레이 변화

- 카인·카즈린은 기존 선택으로 방침을 정한 뒤 상대의 다음 움직임을 읽고 대응한다. 찌르기는 창 흘리기, 횡공격은 비켜딛기, 회수 중 열린 틈에는 검로 잇기를 사용한다.
- 카인은 한 번의 공격과 회수를 반복한다. 카즈린은 횡공격과 찌르기를 모두 받아야 반격할 틈이 생긴다.
- 균형 6·호흡 4로 시작한다. 승부 진행 3에 도달하면 결과를 확인할 수 있다. 균형 0이 되거나 18동작 안에 진행 3을 채우지 못하면 같은 방침으로 재시도한다. 대기 시간은 흐르지 않는다.
- 연민은 호흡·균형 회복, 통찰은 방어 호흡 소모 면제, 결의는 반격 진행 +2와 실수 시 균형 3 감소로 구분한다. 실행 전 변화와 사용할 수 없는 이유를 보여 준다.
- 하도리전은 첫발 한 번으로 한 방 패배에 도달한다. 정상적인 이야기 진행이며 재도전이나 승리 보상을 요구하지 않는다. ‘의무동에서 눈뜨기’를 누른 뒤 기존 후일담 선택이 나온다.
- 결과 확인 뒤 다음 대결로 이동한다. 입단 선서는 기존 장면과 조건을 유지하고, 첫 공식 작전의 선택·편성·출전 준비로 이어진다.
- 대결 화면·타이틀에서 현재 상대와 진행을 표시한다. 의무동 등 이야기 화면으로 돌아오면 제목에 초점을 옮긴다.

## 저장·보상·세계관

선택할 때 기존 성향·평가 점수·동료 관계 수치를 한 번만 적용하고, 카인·카즈린의 결과 플래그와 기억은 승부 확인까지 보류한다. 행동·재시도·확인으로 새 XP나 능력치를 지급하지 않는다. 상태는 선택 필드 `originStory.captainTrials`에 세 장면별로 저장한다. 장면·시도·동작과 슬롯 세대를 대조하여 중복·늦은 입력을 거부한다.

구세이브의 이미 지급된 선택 수치는 보존한다. 대결 상태 없이 현재 장면의 선택만 남은 구세이브는 준비 상태로 이어받고, 이미 다음 장면이나 입단까지 진행한 저장은 재대결하지 않는다. 하도리 후일담을 이미 선택한 구세이브도 패배를 재생하지 않는다.

라온의 카인전 승리, 카즈린에게 근소한 승리, 하도리에게 한 방 패배와 최종 조장 순위를 유지했다. 원전·기존 이야기 데이터·정식 전투 수치와 성장 규칙은 변경하지 않았다. 기존 하도리 본문과 통찰 선택 결과의 꽃잎 순번 불일치 자체는 원문에 남겨 두고 문서에 명시했으며, 새 하도리 안내에는 순번을 넣지 않았다. 구현 계약은 `docs/CAPTAIN_TRIALS_PLAYABLE.md`에 있다.

## 검증

- 24개 테스트 파일, **356개 통과**. 이전 312개에서 44개 증가했다: 대결 규칙·진행 36개, 화면 SSR 7개, 손상 저장 사례 1개.
- 여섯 선택의 도달 가능한 공방 상태, 호흡 부족, 카즈린의 두 방어 연결, 마지막 동작 성공·중단, 재시도, 하도리 후일담 순서를 검사했다.
- 저장 복원·잘못된 장면별 상태 거부·구세이브 이행·중복 보상 방지·이전 장면/시도의 늦은 입력 차단을 검사했다. 입단 후 첫 공식 작전 시작까지 정식 전투 수치가 유지되는지도 자동 검사했다.
- 최종 검토에서 호흡 0의 반격 안내와 균형이 남은 동작 제한 초과 안내를 수정했고, 해당 경계를 포함한 SSR 7개를 다시 통과했다.
- TypeScript·전체 ESLint·프로덕션 빌드·Git 공백 검사 통과. 대결 화면을 별도 청크로 불러오며 기존 수로·폐광·수련·정식 전투 모듈을 유지한다. 제작자 전용 청크는 배포에 포함되지 않는다. 기존 Phaser 대형 청크 경고는 남아 있다.

실제 화면 확인: 카인 통찰 선택·대결 시작·키보드 첫 방어·390px 대응 폼까지 확인했다. 마우스 시간 초과가 복구 뒤 재발했고, 추가 재연결 없는 키보드 대안도 시간 초과되어 세 경기/입단/첫 작전 전체 흐름은 검증하지 못했다.

확인한 항목:

- 새 격리 origin 슬롯1에서 실제 save/load API로 준비한 카인 선택 전 화면을 열었다. 앞선10장면은 시드이며 수련만 실제 API 완료 준비이다.
- 카인 통찰 선택을 실제 클릭하여 ready에 진입한 저장을 다시 읽었다. 대결 시작 버튼으로 실제 active 화면에 진입했다.
- 키보드 Left로 창 흘리기 라디오를 선택하고 Tab으로 제출 버튼에 초점을 옮긴 뒤 Enter로 첫 방어를 실행했다. 실행 후 AX는 turn1/poise6/breath4/progress0 및 창 회수·반격 가능을 표시했다.
- 390px 대응 폼 스크린샷에서 라디오·예측·제출 버튼의 배치를 확인했다. document client/scroll/body 폭381, viewport390으로 관찰한 폼의 가로 넘침이 없었다.

남은 확인:

- 타이틀 이동 클릭은 도구 시간 초과로 완료 여부 불명. 타이틀 저장·새로고침·재개 및 첫 동작 이후 저장 재읽기는 미확인이다.
- 카인 나머지5동작/결과 확인, 카즈린9동작/결과 확인은 실행하지 못했다.
- 하도리 선택 전 ready→한 방 패배→의무동 확인→반응 선택 표시 순서는 실제 브라우저에서 미확인이다.
- seventh-oath 선택/입단/입단 저장 재개/첫 작전 선택·준비·mode-select 진입은 실제 브라우저에서 미확인이다.
- 각 경기 결과 확인의 추가 보상 없음, 최종 점수/친밀도/유대/입단 기록 대조는 미확인이다.
- 보조 실패 시드와 실제 재도전은 준비 코드만 작성했고 브라우저 실행하지 않았다.

검증 한계:

- CDP Input.dispatchMouseEvent timeout703ms가 첫 radio 클릭에서 발생했다. getTab으로 한 차례 복구했고 라디오 선택이 실제 적용된 것을 확인한 뒤 키보드 첫 방어는 성공했다.
- 타이틀 이동 클릭에서 동일 CDP Input.dispatchMouseEvent timeout1225ms가 다시 발생해 해당 흐름을 중단했다. 도구 입력 단계의 시간 초과로 게임 기능의 성공·실패를 확정하지 못했다.
- 루트 요청으로 기존 연결에서 키보드만 쓰는 대안을 한 차례 추가 확인했다. DOM 읽기는 성공했으나 Tab→Right→Right 시도에서 CDP Input.dispatchKeyEvent timeout10000ms가 발생해 즉시 중단했다. 추가 getTab·마우스 재시도는 없었다.
- 자동 검사356개/타입/ESLint/production build 통과는 루트가 수행한 별도 근거다. 미완료 브라우저 흐름을 자동 검사와 합쳐 수동 통과로 주장하지 않는다.
- 최근 warn/error 조회(limit12)는 빈 배열이었다. 모든 브라우저 오류가 없었다는 뜻은 아니며 CUA의 마우스·키보드 입력 오류는 별도로 기록했다.
- 이전10장면과 수련은 이번 수동 검증 범위 전 준비이고 사용자 기존 origin/storage를 접근하지 않았다. 별도 fixture build로 원본 src/dist는 보존했다.
