# 라온제나 다섯 번째 작업 묶음 보고서

2026-09-15 · 폐광 선발시험의 구조 지휘 플레이

선발 11일차 폐광 장면을 선택→동료 명령→구조→전원 철수→선발 12일차 평가로 연결했다. 선택만으로 성공을 기록하던 부분을 고쳐 실제 철수 뒤 결과를 확정한다. 15개 파일을 로컬 커밋으로 보존했고 **278개 테스트·타입 검사·린트·프로덕션 빌드가 통과**했다.

## 플레이에서 바뀐 점

- 두 통로에 고립된 지원자에게 접근하고, 구조를 보조하고, 출구로 이끄는 세 단계를 진행한다. 매 턴 라온과 레오에게 각각 왼쪽 구조·오른쪽 구조·통로 받치기 중 하나를 지시한 뒤 두 명령을 함께 실행한다.
- 통로 버팀은 6에서 시작해 최대 8이다. 받치기로 회복한 뒤 하중을 소모한다. 매 세 번째 명령에는 하중 3, 그 외에는 2이며 다음 하중과 명령 실행 후 버팀 예상을 화면에 표시한다.
- 연민은 카즈린의 구조 지원으로 받치기 한 명령당 버팀 +3, 통찰은 두 사람이 서로 다른 통로를 구조하면 하중 -1, 결의는 라온의 첫 받치기 뒤 하도리에게 하중을 넘기는 흐름이다.
- 두 지원자를 8턴 안에 출구로 이끌고 버팀이 남아야 철수할 수 있다. 버팀 소진이나 시간 초과는 시도 중단이며 같은 선택으로 재도전한다. 두 지원자가 도착해도 라온이 ‘모두와 함께 철수’를 확인하기 전에는 성공 사실을 기록하지 않는다.
- 실행한 명령·통로별 진행·버팀·시도 횟수·현재 단계를 저장하고, 타이틀에 현재 상태를 표시한다. 선택만 하고 실행하지 않은 명령 조합은 진행 기록에 포함하지 않는다.
- 철수 뒤 다음 날의 기존 ‘발전 보류’ 장면으로 이어진다. 기존 성향·평가 점수·레오 관계는 선택 의도로 한 번 지급하고, 재도전과 철수로 경험치나 선택 보상을 추가하지 않는다.

## 기존 저장과 세계관

v10 저장의 선택 필드 `originStory.fieldExam`을 사용한다. 구버전에서 폐광 선택만 한 기록은 선택·점수·관계를 보존한 준비 단계로 이어받고, 미리 기록된 성공 플래그와 NPC 기억은 실제 철수까지 보류한다. 폐광 장면을 이미 끝냈거나 후속 장면·입단까지 진행한 저장은 재시험을 요구하지 않는다. 완료된 수로 구조 기록과 폐광 진행이 함께 저장되는 자연스러운 흐름도 검사했다.

폐광과 고립 지원자 두 명은 기존 게임 각색이다. 원전의 ‘폐쇄구역 13호’와 제작자용 자료의 독·침투 사건을 합치지 않았다. 원전과 기존 이야기 데이터는 변경하지 않았으며, 초기 라온에게 16꽃잎·완성된 방벽·장시간 괴력을 주지 않았다. 마루 수련·체능 완성·라온 제2조장과 여섯 명의 입단 흐름도 그대로다.

## 검증

- 20개 테스트 파일의 **278개 테스트 통과**. 이전 묶음 239개에서 39개 늘었다.
- 새 구조 규칙 25개와 화면·이어가기 SSR 13개, 저장 손상 사례 추가를 포함한다. 세 선택에서 모든 도달 가능한 명령 조합을 순회해 정상 출력의 저장 유효성을 확인했다.
- 세 경로의 실제 규칙 실행, 행동별 저장·로드, 붕괴 우선 판정·마지막 턴 성공·실패·재도전, 오래된 시도·중복 명령 차단, 조기 다음 장면 차단, 완료 기록 한 번 적용과 구세이브 호환을 검사했다.
- TypeScript·전체 ESLint·프로덕션 빌드·Git 공백 검사 통과. 새 구조 화면은 필요할 때 불러오며 기존 마을·정식 전투 모듈은 유지되고 제작자 전용 자료는 배포 청크에서 제외된다. Phaser 대형 청크 경고는 기존과 같이 남아 있다.

실제 화면 확인: 실제 UI로 통찰(split-route) 한 경로의 선택→준비→시작→키보드 명령→타이틀 저장/새로고침/재개→3턴 구조→전원 철수→선발12일차를 완료했다. 저장 재읽기에서 진행·점수·레오 친밀도 보존을 확인했고, API 실패 시드의 실제 재도전도 확인했다. 390px 폼·완료 화면 가로 넘침이 없었다.

확인한 항목:

- 선택 전 장면 시드에서 실제 통찰 선택 '레오와 구조하고 카즈린은 깃발을 지킨다'를 눌러 ready 화면에 진입했다. 실제 저장값은 score6·레오친밀도4·leo:raon유대4, 완료flags없음이었다.
- 실제 구조 지휘 시작 버튼으로 attempt1/active/turn0/integrity6에 진입했고, 명령을 고르기 전 실행 버튼은 비활성화됐다.
- 라온 오른쪽 라디오 클릭 후 Left키로 왼쪽을 선택하고, Tab/Right키로 레오 오른쪽을 선택했다. 실제 DOM checked 값은 raon:left와 leo:right였다.
- Tab/Enter로 폼을 제출하자 정확히1턴, integrity5, left1/right1이 됐다. 선택 라디오가 모두 해제되고 실행 버튼이 다시 비활성화됐다.
- 타이틀에 '폐광 구조 중 · 1턴 · 통로 버팀5'가 표시됐다. 실제 새로고침→라온의 이야기 계속 후 같은 상태가 복구됐고, 실제 save-read 요약 전체가 재로드 전후 동일했다.
- 실제 폼 명령 두 번을 더 실행해 turn3/integrity2/left3/right3의 return 상태가 됐다. 화면에 두 지원자 출구 도착과 별도 철수 확인이 표시됐고 실제 저장값에는 아직 완료flag/완료 사실이 없었다.
- 실제 '모두와 함께 철수'를 누르자 complete가 됐고, '선발12일차·다음장면'을 눌러 suspended-candidate '발전 보류', '선발12일차·심야' 장면으로 이동했다.
- 12일차의 실제 save-read에서 exam.complete와 field-exam 완료 장면, field-split-command flag 및 완료 사실이 추가됐다. score6·레오친밀도4·유대4는 선택 직후와 같아 추가 증가가 없었다.
- API로 만든 failed 시드(attempt1/turn3/integrity0)에서 실제 같은 선택 재도전을 눌렀다. save-read에서 split-route 유지, attempt2/active/turn0/integrity6/left0/right0, score6·친밀도4·유대4·완료flags없음을 확인했다.
- 390x844에서 명령 폼과 완료 화면의 innerWidth390/clientWidth381/scrollWidth381/body381을 확인했다. 스크린샷에서 명령 라벨과 완료·다음 장면 버튼이 가로 잘림 없이 보였다.

남은 확인:

- 연민(rescue-team)·결의(defy-order) 두 경로의 전체 수동 UI 완주는 이번 검증에서 하지 않았다. 세 경로 전체 검증은 root의 core tests 범위이며 수동 완주로 기록하지 않는다.

검증 한계:

- 이전 서장 7개 장면 완료는 fixture 설정이며 그 서장을 실제 플레이한 검증이 아니다. currentSceneId field-exam부터의 선택과 통찰 완주는 실제 UI 조작이다.
- 실패 상태는 실제 core API의 LL→RR→LR 계획으로 생성한 시드다. 실패까지 브라우저에서 플레이하지 않았고, 시드 이후 재도전 버튼만 실제 UI로 검증했다.
- 모든 저장 접근은 새4398 테스트 origin의 슬롯1에 한정했다. 기존 사용자 저장 origin/storage와 사용자 탭은 수정하지 않았다.
- 폼의 키보드 검증은 표준 라디오 방향키, Tab, Enter 제출 범위다. 터치 장기 홀드 또는 보조기술 전체 접근성을 검증한 것은 아니다.
- 마지막 warn/error 로그 최신12개 조회는 빈 배열이었다. 이는 해당 조회 범위의 관찰이며 전체 애플리케이션 무오류 보장을 의미하지 않는다.
