# 라온제나 여섯 번째 작업 묶음 보고서

2026-09-15 · 마루의 열여섯 꽃잎 수련

기존 ‘힘이 빠진 열여섯 꽃잎’ 장면을 **방침 선택 → 보법·무게·호흡 조절 → 열여섯 궤적 연결 → 마루 앞 마무리 → 조장 선발전**으로 연결했다. 15개 파일을 로컬 커밋으로 보존했다. 전체 **312개 테스트·타입 검사·린트·배포용 빌드가 통과**했다.

## 플레이 변화

- 열여섯 꽃잎 모양의 진행도를 보며 다음 동작을 고른다. 선택하면 실행 후 궤적·부담을 미리 보여 주고, 실행 버튼을 누를 때 한 동작이 흐른다. 읽거나 자리를 비운 시간은 흐르지 않는다.
- 기본 보법은 궤적 +3·부담 +2, 무게 나누기는 +2·+1, 호흡은 부담 -3이다. 부담은 0 아래로 내려가지 않고, 0일 때는 호흡을 고를 수 없다.
- 연민은 호흡의 부담 감소가 4, 통찰은 무게 나누기의 궤적 증가가 3, 결의는 보법의 궤적 증가가 5·부담 증가가 3이다.
- 10번의 동작 안에 궤적 16개를 이어야 한다. 부담이 8에 닿으면 마지막 궤적에서도 중단한다. 10번째 동작에서도 목표를 이루고 부담이 한계 미만이면 성공할 수 있다.
- 호흡을 골라도 이어 온 궤적은 유지된다. 한계나 동작 소진으로 중단하면 같은 선택으로 다시 연습한다. 횟수는 수련 몽타주의 반복을 나타내며 실제 날짜·영구 부상·선발 탈락으로 바꾸지 않는다.
- 목표 도달 뒤 ‘마루 앞에서 수련 마무리’를 확인해야 결과를 기록한다. 그 후 기존 조장 선발전으로 넘어간다. 부담 한계와 목표에 동시에 닿는 경우에는 화면도 중단을 표시한다.
- 실행한 동작·궤적·부담·시도·단계와 기록을 저장하며, 타이틀에서 현재 상태를 확인하고 이어간다. 고르기만 하고 실행하지 않은 동작은 저장 진행에 포함하지 않는다.

## 저장과 세계관

선택할 때 기존 성향 +1, 점수 6/7/7, 마루 친밀도 +2를 한 번 유지한다. 완료 플래그·기억만 마무리까지 보류하고, 재도전이나 확인으로 추가 경험치·스킬·능력치를 주지 않는다. 마루는 편성 동료가 아니므로 새 동료 유대 보상을 만들지 않았다.

v10의 선택 필드 `originStory.petalTraining`으로 저장한다. 구버전에서 선택만 한 수련 장면은 기존 수치를 보존해 준비 단계로 이어받고 조기 완료 사실만 보류한다. 이미 수련을 마쳤거나 이후 장면·입단까지 진행한 기록은 재수련하지 않는다. 수로·폐광 완료 상태와 수련 상태가 함께 남는 저장도 검사했다.

마루는 기억한 궤적을 짚어 주고 라온이 자기 몸으로 재구축한다. 수련은 열여섯 움직임을 한 번 이은 성취로 표현했다. 원전, 기존 이야기 데이터, 본편 16꽃잎 스킬·피해·사기·성장 규칙을 그대로 유지했다. 구현 계약은 저장소 `docs/PETAL_TRAINING_PLAYABLE.md`에 있다.

## 검증

- 22개 파일, **312개 테스트 통과**. 이전 278개에서 34개 증가했다.
- 수련 코어 25개, 화면 SSR 8개, 저장 손상 사례 1개를 추가했다. 세 선택의 모든 도달 가능한 규칙 상태에서 행동과 저장 유효성이 일치하는지 확인했다.
- 각 행동 뒤 저장·로드, 한계 우선·마지막 동작 성공·재도전, 이전 시도와 중복 입력 거부, 조기 장면 이동 차단, 마루 결과 기록 한 번 적용, 구세이브 이행을 확인했다.
- 전체 TypeScript·ESLint·프로덕션 빌드·Git 공백 검사 통과. 수련 화면은 필요할 때 불러오고, 기존 마을·폐광·정식 전투 모듈은 유지한다. 제작자 전용 청크는 배포에 포함되지 않는다. 기존 Phaser 대형 청크 경고는 남아 있다.

실제 화면 확인: 통찰 수련의 실제 선택·키보드 동작·저장 재개·6동작 마무리·조장 선발전 진입을 확인했다. 16꽃잎/부담8 실패 시드의 표시와 실제 재도전도 확인했다.

확인한 항목:

- 선택 전 장면 시드에서 실제 통찰 선택 → 수련 준비 → 시작 버튼으로 active에 진입했다.
- 첫 동작은 trace 라디오 클릭 뒤 Right로 balance 선택, Tab으로 제출 버튼에 초점, Enter로 실행했다. 실제 turn1/petals3/burden1이며 선택이 초기화됐다.
- 타이틀 이동 → 실제 새로고침 → 이야기 계속으로 수련을 재개했다. 재개 전후 실제 save/load 전체 요약이 동일했다.
- 실제 UI로 balance를 총 6회 실행해 review/turn6/petals16/burden6에 도달했다. 완료 전 flag와 완료 기억은 없고 수련 방법 기억만 있었다.
- 마루 앞에서 수련 마무리를 실제 클릭해 complete가 됐고 조장 선발전으로 버튼을 통해 captain-trials/재능이 예상하지 못한 검/최종 조장 선발전 화면으로 이동했다.
- 최종 저장은 selectionScore7, maruAffinity2, bondLevels빈객체, petals-distributed flag 및 완료 기억을 보유했다. 선택 전과 heroProgress/파생 HP·armor·skill/자원이 동일했다.
- 실제 core API의 결의 trace→trace→balance→trace 실패 시드는 petals16/burden8/turn4/failed였고 UI는 잠시 멈춤·부담 한계·다시 연습으로 표시했다.
- 실패 시드에서 쉬고 다시 연습을 실제 클릭했다. attempt2/active/turn0/petals0/burden0으로 초기화됐고 score7/affinity2/heroProgress/파생수치/자원이 유지됐다.
- 390px 폼·완료·상단 SVG 캡처 모두 document/client/body 폭381, viewport390으로 가로 넘침이 없었다. 선택·제출 버튼, 완료 문구·다음 버튼, 16꽃잎 그림의 배치를 육안 확인했다.

남은 확인:

- 연민·결의 경로 전체 실제 UI 완주 및 320px 화면은 이번 범위에서 실행하지 않았다.
- 앞선 10개 서장 장면과 수로 구출·야외 선발 과정은 이번 fixture에서 실제 플레이하지 않았다.
- 이전 묶음의 야외 선발 rescue-team/defy-order 실제 완주와 마을 카즈린 귀환 확인은 이번 수련 검증과 별개의 미확인 항목이다.

검증 한계:

- 앞선 10개 장면 완료 ID는 시드 준비다. 통찰은 현재 장면 선택부터 실제 UI로 진행했고 실패 경로 4동작은 실제 core API 시드다. 실패의 재도전 버튼만 실제 UI로 실행했다.
- 별도 production-mode fixture가 실제 App/CSS를 가져온다. fixture chunk 이름은 production과 다르며 원본 src/dist는 수정하지 않았다.
- warn/error 최근 조회(limit12)는 빈 배열이었으며 모든 세션·브라우저 오류가 없다고 단정하지 않는다.
- 이번 새 4402 탭에서는 transport 실패가 발생하지 않았다. 과거 별도 follow-up 탭 실패는 해당 보고서에 남겨 두었다.
- 전체 312개 테스트·타입·ESLint·production build 통과는 루트가 실행한 자동 검사이며 이 수동 검증 결과와 구분한다.
