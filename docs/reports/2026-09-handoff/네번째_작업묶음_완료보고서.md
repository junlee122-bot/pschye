# 라온제나 네 번째 작업 묶음 보고서

2026-09-14 · 정식 작전의 저장·재개·보상 정산

정식 작전을 시작한 뒤 중단·재접속해도 전투를 이어갈 수 있게 했다. 전투 결과를 확인하지 않고 보상을 처리하던 경로도 수정했다. 25개 파일을 로컬 커밋으로 보존했고 **239개 테스트·타입 검사·린트·프로덕션 빌드가 통과**했다.

| 기타 오류 | 전투 재개 후 로그 ID 충돌을 막고, 적 전멸과 목표 파괴가 동시에 발생하면 패배로 처리한다. |

## 검증

- 18개 테스트 파일의 **239개 테스트 통과**. 이전 묶음의 185개에서 54개 늘었다.
- 저장 JSON 왕복, 출전 조건, 출전 정보 고정, 액션 타이머 재기준화, 손상된 기록 거부, 오래된 콜백 차단, 승리 복구·중복 보상·출격조 보상을 검사했다.
- 별도 전술 엔진 검사에서 **2,400전투의 상태 48,794개가 모두 저장 검증을 통과**했다. 4~6명 편성, 세 난도, 두 교리, 높은 전쟁 압박, 최대 로그·연계·라운드 경계를 포함했다. 이는 결정적 엔진 검증이며 실제 브라우저 플레이와 구분한다.
- TypeScript·전체 ESLint·프로덕션 빌드·Git 공백 검사를 통과했다. 제작자 전용 자료실이 배포 청크에 포함되지 않는 것도 확인했다.
- Phaser 대형 청크 경고는 남아 있다. 액션 종료 이벤트의 동기 저장은 코드 경로를 확인했으며, 운영체제 강제 종료까지 보장하는 기능은 아니다.

실제 브라우저 결과: 격리 origin에서 전술 실제 undo·저장 종료·새로고침·재개, 액션 실제 명령·저장 종료·새로고침·체크포인트 보존, 승리 자동 정산 후 재로드 중복 방지를 관찰했다. 390px 저장 카드와 액션 재개 안내는 가로 넘침이 없었다. 발견한 승리 화면 넘침·문구는 root가 수정했고 최종 fixture 빌드는 완료했으나 CUA 연결 단절로 수정 화면 재확인은 미완이다.

확인한 항목:

- 전술 API 시드(철문·측면 유도 2행동)가 타이틀의 '저장된 작전 이어하기'를 통해 실제 전투로 열렸다. 화면에 지휘점 2/4, 사기 56이 표시됐다.
- 실제 행동 취소 및 저장하고 나가기 후 실제 저장 재읽기에서 지휘점 3, 사기 32, 이력 깊이 1, 저격수 HP117·은폐·노출0을 확인했다.
- 새로고침 후 전술 이어가기에 지휘점 3/4·사기32·숨은 적·활성 행동 취소가 유지됐다. 남은 취소를 실제 클릭하고 나간 뒤 Hub의 방벽이 63에서 초기 26으로 돌아왔다.
- 390px Hub 저장 카드는 스크린샷에서 버튼·안내가 보였고 innerWidth390/clientWidth381/scrollWidth381로 가로 넘침이 없었다.
- 액션 직렬화 시드가 재개 전 일시정지 안내로 열렸고 생명115/139·사기32·방벽63이 일치했다. 390px 안내와 양쪽 선택 버튼은 화면에 들어왔고 clientWidth/scrollWidth 모두390이었다.
- 액션을 실제 재개해 레오 명령을 클릭하자 방벽+40·사기+14 로그와 수치가 표시됐다. 실제 일시정지, 재개, 저장하고 나가기, 새로고침, 이어가기를 수행했다.
- 액션 종료 전후 저장 재읽기의 battle/action 객체가 완전히 같았다. elapsed8.600219999408719초, HP97, 좌표382/389, 레오 cooldown5422.3466669003155ms, 하도리449.78000059128135ms가 유지됐고 재개 대기 화면에도 HP97·사기46·방벽85가 일치했다.
- 실제 엔진 기술/턴으로 만든 미정산 승리 시드(round2)가 App 로딩에서 정산됐다. 보급320→410·정보40→70·유물0→1·명성0→45·라온XP8→78, 완료 임무1·careerMissions1·settled=true를 확인했다.
- 실제 '저장된 결과 보기'와 새로고침 뒤 보상·진행·attempt를 포함한 저장 요약 전체가 최초 정산 값과 같았다.

미확인·추가 확인 항목:

- 최종 fd9b941의 settled 결과에서 동일 임무 선택 변경·재출전 경로는 이 fixture 이후 수정되어 브라우저 미검증.
- 320px 및 연속 터치 홀드 이동은 미검증. 모바일 오른쪽 버튼 단일 클릭은 체크포인트 좌표를 바꾸지 않아 실제 이동 성공으로 기록하지 않았다.
- 출전 준비/방식 선택 및 액션 initial 시드는 준비했으나 이번 핵심 검증에서는 직접 사용하지 않았다.
- 390px 승리 화면의 14px 넘침과 첫 승리의 재현 안내 문구를 root가 수정했지만, 최종 빌드 뒤 CUA debugger 연결 실패로 실제 화면 재확인은 미완.

검증 한계:

- 테스트 전용 4397 origin 슬롯1이며 기존 사용자 origin/storage는 접근하지 않았다.
- 서장 완료는 시드 전제다. 전술 시작 2행동과 승리까지의 전투는 엔진 API 시드이며 브라우저 전체 플레이를 의미하지 않는다.
- 액션 시드의 최초 좌표382/389·elapsed1.25초·생명 손상·재사용 대기는 검증용 지정값과 실제 순수 규칙/serializer로 구성했다. 이후 레오 명령·전투 시간 진행·저장 종료는 실제 UI에서 수행했다.
- 브라우저 제어는 CUA만 사용했다. 비동기 검사 결과를 너무 일찍 읽은 JS 오류와 details summary의 역할 선택자 no_matches가 각1회 있었다. AX 인덱스 확인 후 정상 진행했으며 연속 transport/CDP 장애는 발생하지 않았다.
- 마지막 warn/error 최근12개 로그 조회는 빈 배열이었다. 전체 세션 무오류를 보장하는 근거로 사용하지 않는다.
- 최종 UI 재검증 때 기존 탭1908172948에 'Debugger is not attached' 발생. 인벤토리 조회 후 getTab으로 한 번 복구했으나 같은 오류로 실패하여 추가 검증을 중단했다.

## 이전 마을 구간의 추가 확인

이전 묶음의 수로 귀환 상태에서 실제 마을 이동으로 카즈린의 대화 가능 거리까지 도착했고, 새로고침 후 귀환 단계와 좌표가 유지되는 것을 확인했다. 이후 귀환 확인 버튼의 브라우저 도구 호출이 시간 초과되어 최종 확인→일주일 뒤 장면 전환은 미확인으로 남긴다. 상세는 [마을 후속 관찰](fourth-batch-village-followup.md)에 있다.
