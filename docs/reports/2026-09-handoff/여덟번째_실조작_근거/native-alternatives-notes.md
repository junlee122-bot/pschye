# 대체 성향의 실제 입력 검증

2026-09-15 · Edge 153.0.4234.32 · 격리 origin http://127.0.0.1:4409/ · 기준 bbcf10e / index-BVMjwOsu.js

루트가 새 게임에서 실제 조작으로 얻은 선택 직전 체크포인트를 별도 브라우저 context에 복제했다. 이전 장면들은 통찰 경로이며, 각 구간에서 연민/결의를 직접 선택했다. 따라서 세 성향의 새 게임 전체 연속 완주가 아니라, 정상 저장에서 갈라진 대체 구간 10개 검증이다.

| 구간 | 성향 | 실제 입력과 결과 |
|---|---|---|
| 수로 | 연민·결의 | 방어 버튼을 Enter로 24회 실행해 행동 제한 실패 → 재시도 2회차 → 각각 9/7동작으로 구조·철수 → 마을 이동 → 카즈린 귀환 확인 → 선발 공고일 |
| 폐광 | 연민·결의 | 두 사람 모두 버티기로 실패 → 재시도 → 실제 두 라디오 명령으로 구조 → 철수 확인 → 다음 장면 |
| 마루 수련 | 연민·결의 | 같은 추적 동작을 반복해 부담 한계 실패 → 재시도 → 성향별 동작으로 수련 → 결과 확인 → 다음 장면 |
| 카인 | 연민·결의 | 회복을 반복해 실패 → 재시도 → 각각 8/4동작 승부 → 결과 확인 → 카즈린 |
| 카즈린 | 연민·결의 | 회복을 반복해 실패 → 재시도 → 각각 15/9동작 승부 → 결과 확인 → 하도리 |

각 사례는 실제 버튼/라디오 입력과 LocalStorage 재읽기를 대조했다. phase, turn, attempt, 선택 점수, 결과 flag, 성장/관계 값을 기록했다. 실패와 재시도로 선택 보상이 반복되지 않았고, 성공 직후 확인 대기에는 결과 flag가 아직 없으며 확인 후 한 번만 추가됐다. UI 정상 입력으로 완료 장면 ID가 등록되는 것도 확인했다. 직접 phase·승패·보상 값을 주입하거나 규칙 API를 호출하지 않았다.

원본 근거는 native-alternatives-forms-result.json(8/8)과 native-alternatives-river-result.json(2/2)이다. 폼 기록의 errors는 pageerror 수집이며 console 전체 수집은 아니다. 수로 기록은 pageerror와 warning/error console을 수집했다. 스크린샷은 390×844 전체 페이지이며 대표 카즈린 완료/수로 화면을 시각 검토했다.

초기 수로 스크립트는 첫 active 저장이 보인 직후 전역 q를 입력하고 턴 변화가 없어 시간 초과됐다. 후속 화면에서 active/turn 0을 확인했다. 브라우저 입력 리스너 준비까지 확인하지 않은 실행이므로 이것만으로 원인을 확정하지 않았다. 후속 검증에서는 실제 표시된 동작 버튼을 Enter로 활성화했고 모든 행동이 정상 반영됐다. 이 결과를 q 단축키의 통과로 바꾸어 기록하지 않는다. 과거 서버 중단/선택자/초기 준비 실패 기록은 별도 previous 파일에 보존했다.

브라우저와 모든 context는 종료했다. 루트의 정적 서버는 정식 전투와 수정 후 재검증을 위해 유지했다.
