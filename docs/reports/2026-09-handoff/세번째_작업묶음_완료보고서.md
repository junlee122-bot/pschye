# 라온제나 세 번째 작업 묶음 보고서

2026-09-14 · 첫 마을의 구출·귀환·저장 흐름 연결

첫 마을의 이동→대화→선택→수로 구출→귀환 확인→다음 장면 흐름을 구현했다. 14개 파일을 로컬 커밋으로 보존했고 전체 185개 테스트·타입·린트·프로덕션 빌드가 통과했다. 이번 교전은 기존 2D 시제품 안의 작은 턴 방식 구출이다.

## 플레이에서 바뀐 점

| 구간 | 구현 내용 |
| --- | --- |
| 선택 | 수로에서 선택한 방법을 고정한다. 선택만으로 아이가 구조되었다는 결과를 표시하지 않는다. |
| 연민 | 아이 가까운 4·5열에서 세 번 목소리로 길을 알려 준다. 아이가 직접 빠져나온다. |
| 통찰 | 2·3·4열에 각각 돌을 놓아 다른 사람도 따라갈 수 있는 경로를 만든다. |
| 결의 | 3·4·5열에서 세 번 생물의 시선을 끌어 카즈린이 아이를 구조할 틈을 만든다. |
| 소규모 교전 | 5열×3행 지도에서 이동·구출 행동·방어를 조작한다. 예고된 돌진 행에서 행동을 마치면 피해를 받는다. 입력할 때만 턴이 흐르며 체력은 5, 제한은 24턴이다. |
| 성공과 재도전 | 구출 진행 3을 채운 뒤 라온도 1열로 철수해야 성공한다. 생물 처치는 요구하지 않는다. 실패하면 같은 선택으로 다시 시작한다. |
| 마을 귀환 | 수로에서 마을 지도로 돌아와 공동회관 앞 카즈린에게 접근한다. ‘무사 귀환 확인’으로 결과를 남긴 다음 ‘일주일 뒤 · 선발 공고일’로 넘어간다. |
| 기억 | 카즈린의 귀환 대사가 선택에 맞게 달라진다. 성공 플래그·NPC 결과 기억·활동 기록은 귀환 확인 때 한 번만 추가한다. |
| 저장과 조작 | 교전 행동, 체력, 표식, 시도 횟수, 실패·귀환 단계가 저장된다. 타이틀에서 현재 구출 단계를 보여 준다. 마을의 마지막 이동 위치도 저장하고, 대화 중 이동을 멈추며 모바일 방향 버튼을 길게 눌러 이동할 수 있다. |

## 기존 기록과 세계관

저장 버전과 키는 v10을 유지한다. 이미 수로를 완료했거나 후속 장면·입단까지 진행한 저장은 다시 구출시키지 않는다. 수로 선택만 남은 예전 저장은 구출 준비로 이어지며, 기존에 지급된 성향·평가·관계 수치는 다시 지급하지 않는다. 새 선택도 이 수치는 선택 의도로 한 번 기록하고, 성공 사실은 실제 귀환까지 보류한다. 손상된 구출 상태는 저장 복구 절차에서 판별한다.

수로 교전은 기존 오프닝 설계의 각색 구현이다. 원전 본문과 세계관 JSON은 변경하지 않았다. 초기 라온에게 입단 후 성장·16꽃잎·본편 동료 기술을 적용하지 않았으며, 구출된 아이를 기존 이름 있는 주민과 동일인으로 확정하지 않았다.

## 검증 결과

- 15개 테스트 파일의 **185개 테스트 통과**. 새 구출 회귀 17개가 포함된다.
- 세 선택의 실제 행동과 철수, 행동마다 저장·로드, 실패·재시도, 귀환 거리 경계, 중복 보상 방지, 단계별 진행 차단, 기존 세이브 이행과 손상 상태 거부를 확인했다.
- TypeScript·전체 ESLint·프로덕션 빌드·Git 공백 검사 통과. 구출 화면이 배포 모듈에 포함되고 제작자 자료실은 제외됨을 확인했다.
- 원전 변경 없음. Phaser 대형 청크 경고는 기존과 같이 남아 있다.
- 브라우저 확인: 실제 버튼·키보드 3행동 후 새로고침 복원, 390px 가로 넘침 없음, 연민 구출·철수 후 실제 마을 지도와 귀환 목표 표시를 확인했다. 이전 묶음의 빈 슬롯 전환·라온만 표시되는 도감·입단 전 메뉴 잠김도 확인했다.
- 남은 실제 플레이 확인: 카즈린까지 도보 귀환·최종 확인·다음 장면 전환, 다른 두 선택과 실패·재시도의 실제 화면 검증. 귀환 도중 브라우저 자동화 연결이 끊겨 이 부분은 자동 테스트와 코드 검토까지만 완료했다.

실제 화면 검증의 상세 범위와 도구 오류는 [브라우저 검증 기록](third-batch-browser-review.md)에 있다. 자동 저장·로드 테스트와 코드 검토를 실제 전체 마을 완주로 간주하지 않았다.
